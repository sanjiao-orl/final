# 章节起草

本 skill 只管流程,不管姿态——声口按系统提示注入的「声口摘要」行文(没有就先跑「声口建档」或问作者),评判姿态归角色方案。原则一句话:**先拿上下文再动笔,产出一律过审批闸门**。

## 流程(按序执行)

1. **确认目标**:本章 frontmatter 有 goal 先读出来复述给作者确认;没有就问一句「本章要完成什么」,别自己编目标。
2. **拉上下文**(缺什么拉什么,禁止全量拉全书):
   - `list_structure` 定位本章与前后章;
   - `read_chapter` 读前一章(接住结尾节奏)和本章已有内容(已有正文则续写/改写的部分不动,先报告再动);
   - 账本:系统提示若已注入「本章账本切片」直接用它;没有再调 `ledger_chapter_slice` 工具拉本章切片(伏笔该埋该收、道具在谁手里、谁该知道什么,全以切片为准,不凭记忆编造);
3. **起草**:调 `stage_chapter_proposal` 把本章正文提案送进暂存区(作者批量采纳后才落盘),不要在对话里贴大段正文代替提案;`write_chapter` 只在作者明确说「直接写入/立即落盘」时才用(壳侧有审批闸门)。
4. **同步账本**(提案被采纳后的账本同步):正文涉及剧情事实变动时,交差报告里列出「若被采纳需同步的账本条目清单」——新埋伏笔/道具易手/角色得知或失去知情/时间推进,提醒作者采纳后用 `ledger_upsert` 同步落账;不确定该不该记的也列出来问作者。
5. **交差**:报告提案字数、目标章、待同步账本条目清单,建议作者跑「章节体检」或贵档审阅。

## 纪律

- 不发明账本事实:切片里没有的伏笔/道具/知情,正文里需要时先在报告里提出,别默默写进账本。
- 一次一章:别把后续章的内容提前写死。
- 暂存区采纳是铁律:不直接 `write_chapter` 绕过;提案被退回就按作者意见改写后重新进暂存区。
