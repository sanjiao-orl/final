# 4.4 预警雷达批 · 立项方案（待作者审定）

> 规范基线 `docs/reference/05-账本与长篇连续性.md` §裁决回路/§三档处置语义；现状与活账 `docs/current/现状.md` + `bugs.md`。本件只做立项边界与决策点清单，设计细节随批内调研补。

## 一句话目标

三张死表（expect 绊线 / doNotReexplain / tripwires）接确定性消费 → 审阅面板常规输出（预警=反向提案，origin=radar 入统一收件箱）；把裁决机器从「能收提案」补成「会催办」——规范三档处置的顶/列两档落地。

## 范围（四件）

1. **三张死表的确定性消费**：每张表 ≥1 条确定性诊断，产出反向提案入收件箱（origin=radar）。判据全部确定性（结构规范红线：预警不走 LLM 猜），LLM 只可做摘由。
2. **顶/列两档（05 §三档处置）**：顶=伏笔逾期→收件箱置顶；列=悬空、doNotReexplain→常驻清单。表达为收件箱面板的展示档位+条目标记，不改三态状态机契约（契约只加法纪律）。
3. **重报锚消费（接 bugs.md [审计]挂账）**：「有意延后」的 reanchorVolume 接卷映射——到卷前抑制再入、到卷解除；这是 suppressedKeys 三集合（pending/误报/观察）之外的第四种入口守卫，纯派生实现同前。
4. **处置率仪表（05：作者没采取任何行动=误报）**：按条目寿命统计 pending 超期率/驳回理由分布，审阅面板出数（最小形态：读数进「上次读数」位，不做图）。

## 边界（不做）

- 不改 `ProposalStatus` 三态契约与裁决流程（加固批 e50913e 已钉死语义）；预警是「反向提案」走同一状态机，无新状态。
- 不动 severity 四级表达粒度（05 明言不改 review findings 的表达）。
- 不碰 chat 直写路径与注入预算（配额钉扎挂账随真账本实测另结）。
- 预警不做 LLM 判定——死表消费是确定性诊断的职责（结构纪律：结构级检查永远是 domain 工具）。

## 出口（对照北极星）

- 三张死表各 ≥1 条确定性诊断在审阅面板常规可见（盖真章可验：灌诡秘净本，死表命中出数）。
- 顶/列两档在收件箱面板可辨；有意延后到卷抑制实测生效。
- 处置率仪表出数；**裁决负担数据=4.3 真人小段作者实测**（4.2 出口欠账，数据落地触发 0017 §9 重开权判断——雷达批与该实测并行不互堵）。

## 方案内决策点（开工前需作者拍板，其余实现细节自主）

1. **「伏笔逾期」判据的数据源**：promise 表现有 arc(planted/payoff) 结构无「预计回收卷」字段——逾期判定要么引入登记型预计卷字段（登记型直写，静态层），要么以「planted 后 N 章无 payoff」章距阈值替代（零 schema 变更）。倾向后者起步（可配置默认否：缺省关，书级开启）。
2. **置顶的实现位**：人审留 md 纪律下，置顶=面板排序置顶+条目标记（md 结构不动）还是 md 内分区？倾向面板排序（md 区分档会引入重组写风险）。
3. **预警噪音阀门**：三张死表全量消费的首扫可能集中灌箱——沿用扫描管线 maxCandidates 预算闸缺省值，另设书级开关（缺省开或关挂真人小段数据）。
