# 产品定义（QA 对齐实录）

> 来源：第三次出发前的问答对齐（不再事先投放资料，改用问答对齐——根因是 AI 在缺乏完整意图时会替你做几百个隐性决策）。本文是需求基线，后续设计决策不得与之冲突；冲突时改设计，不改本文（除非作者本人修订）。

## 第零轮 · 方法论

**Q：为什么之前做出来和预期相差甚远？**

A：根因是 AI 在缺乏完整意图时替作者做了几百个隐性决策——形态、用户、边界、技术路线全是猜的。

## 第一轮 · 原点

**Q：想解决什么问题？现有方案烂在哪？你是目标用户吗？有形态预感吗？**

A：想用 AI 写小说，现有程序全走"AI 生成、批量生成"路线，不合心意。大量调研后（开源项目、IDE、通用 agent），发现 Codex、带插件的 VS Code 最接近想要的，但它们是编程工具。初步预期：服务于小说写作领域的 Cursor——更好的 agent 工具。

## 第二轮 · 用户与工作流

**Q：写什么？实际流程？Cursor/Codex 哪些交互让你心动？AI 边界画在哪？最痛的瞬间？"深入底层"指什么？**

A：

- 写网文连载长篇。流程：大纲+开头+点子 → 补设定、人物、内容、细纲、结尾。过去用搜索引擎，现在用 AI 提问，每个步骤都能用 AI 提效。
- 心动点：成为完全的工作台——写作之外，讨论、搜索、改写、找灵感都在这里；可扩展（插件/skill/MCP）。
- AI 边界模糊但有一条铁律：能接受它改大部分内容，前提是方向验证一致、经过思考；拒绝批量生成、越往后越崩溃。
- 卡点：想不出情节；细节遣词造句卡壳；脑洞多不会选；中后期作品难以管理。
- "深入底层" = ①比编程产品更精细的结构（现为多文件夹 md+脚本）②AI 更容易理解小说（类 gitnexus 之于代码）。

## 第三轮 · 结构与形态

**Q：自用还是产品化？现有 md 结构交接？走查"更新一章"？理解层要答哪些问题？形态三路线倾向？**

A：

- 自用即可，但别写死，要好迭代维护。
- 现有结构：大纲（总纲/分卷/伏笔坑）+ 设定（角色/时间线/世界观/组织）+ 章节（按卷分目录）+ tools（查章节.py、拆分语料.py）。
- 写作实况：从大纲和前文想出大概剧情 → 丰富细节、填坑埋伏笔 → 反复磨丰富度、描写、遣词、细节不出错；开书/大情节则不停拿想法和 AI 讨论。
- 理解层分两档：日常靠简单设置/结构化总结/脚本快速应答；需要更强能力时接得住。
- 倾向魔改现有工具，不重复造轮子。

## 第四轮 · 约束与 MVP

**Q：用过哪些开源 agent、爱憎？本地约束？MVP 四件事砍哪个？讨论结论去哪？数据模型升哪档？"大毛病"具体是哪些？**

A：

- 本地为主，无账号无云端。
- 最顺手 Codex：能像编辑器一样框选，又不像真编程工具什么都要自己设置。最烦的品类：设置要改配置文件、什么都要 /xx 的 CLI 味产品。
- MVP 什么样不懂，是技术问题——"说不定搞到最后就是少量调整+插件"。
- 想要多个存区：无归属讨论/章节内讨论/正文/尚未采纳的改动区（非重点可砍）。
- 同意 md+frontmatter 起步、为索引库留口。脚本是代替 AI 的机械活：统计字数、出场次数、拆分语料。
- 毛病全都有，红线：读者不觉得"这作者太离谱、在敷衍我"。

## 第五轮 · 最后确认

**Q：模型用谁？要 Tab 续写吗？发布环节管吗？暂存区逐条还是批量？**

A：

- 和编程一样：日常便宜模型（DeepSeek 等），规划/审核/复杂内容切贵模型，key 订阅都有，成本可控。
- Tab 续写原生功能不一定要，思路可采纳——真实需求是在某个地方反复删改卡壳时，有 AI 辅助。
- 发布不管，最终要复制粘贴到平台写作助手，保证复制出去格式直接用就行；章为最小结构。
- 逐条采纳太累，要批量勾选：采纳/整改/丢弃。

## 补充轮 · 两次修正

- 去编程味不是重点，工程量大就先不搞，功能过关优先。
- 数据模型不要照搬旧结构——之前只是凑合用，完整规划还按粗放路线就太弱了。

## 真实需求（从回答里提炼的，比原话更深一层）

1. 要的不是"写小说的 AI"，而是"**写小说的工作台**"。AI 是协作者不是作者——讨论、检索、改写、检查、管理全书都在同一处完成，人始终握笔。
2. 要的是 **Cursor 范式在小说领域的原生实现**，不是编程工具的借用。通用 agent 的能力（聊天、工具调用、扩展）要继承，但数据模型、交互、检查逻辑必须是小说原生的。
3. 核心恐惧是**失控**：批量生成越写越崩是 AI 失控，中后期管理崩坏是结构失控。所以"方向验证一致"和"结构精细"不是两个功能，是同一个需求的正反两面。
4. 质量红线是对读者负责的一致性：伏笔、时间线、口吻、知情权，任何一处离谱都是"敷衍读者"。
5. 务实的工程观：自用、本地、可迭代、不造轮子、功能优先于形态、成本双模型分层。

## 产品定义

**面向网文连载作者的本地 AI 写作工作台——小说领域的 Cursor。** Windows 桌面，纯本地文件，无账号无云。

三条设计原则：

1. **人的方向，AI 的笔**——AI 产出全部先进暂存区，批量采纳才落地；
2. **结构即智能**——AI 懂书靠结构化工程+理解层，不靠通读全文；
3. **可配置默认否**——偏好改 `theme.ts` 发版，不设设置面板。
