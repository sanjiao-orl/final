# 酒馆（SillyTavern）对照调研（2026-08-24）

> 起因：作者发起的范式对照讨论（「小说写作程序和酒馆项目比较有相似性」「引入更现代化 Agent 设计能根本上解决一些问题」），接续「对比前 Agent 时代 AI 写作程序」一轮，本件为定稿沉淀。方法：公开资料查证（官方文档 docs.sillytavern.app、GitHub releases 与 issue、2026 年评测与社区资料）+ 本项目代码实证（本会话 2026-08-23/24 取证）；未做技术逆向。定位：**块 4.0 定稿（角色卡/预警/状态可见性）与 3c 碰撞深化的参考件**；本件归档封存不改写，可采纳结论的现行载体是 `docs/current/现状.md`。

## 一、酒馆现状（2026-08 查证）

### 底座

Node/Express 本地服务（缺省 :8000），前端本地加载；多用户账号体系；BYOK 多后端（OpenAI/Claude/Gemini/DeepSeek/GLM 系 + KoboldAI/TabbyAPI/llama.cpp 本地推理全通吃）；聊天级模型切换与采样器全暴露。核心假设：**叙事 = 聊天记录**——角色扮演在对话中发生，作品即 chat log（JSONL 持久化），导出是附属品。

### 核心结构（逐件：是什么 + 怎么实现）

- **角色卡**：PNG 内嵌 JSON（chara_card_v2/v3 开放规范）——name/description/personality/scenario/first_mes/示例对话/内嵌世界书/备用开场白/creator 元数据。实现上是纯提示词容器：注入即生效，无任何校验。**卡即分享货币**（Chub 等平台养出交换生态）。
- **世界书 / Lorebook**：关键词触发注入引擎。条目=主/副关键词+内容+触发逻辑（AND ANY/NOT ALL 等）+扫描深度（扫最近 N 条消息）+递归触发（条目带出条目）+注入位置/深度/顺序/优先级+触发概率+token 预算；timedEffects 给条目挂 sticky（粘住 N 轮再退场）/delay/cooldown（冷却）——条目级状态机。实现=每次生成前对近期消息做关键词扫描，命中条目按旋钮拼进 prompt。
- **作者注释**：固定深度（离对话底部 N 条）浮空注入，抢模型近端注意力。
- **聊天管理**：多聊天/分支/**swipes**（同一条消息横向重 roll 多版对比）/checkpoints/消息级编辑拖拽/impersonation（替用户写）。
- **群聊**：多角色卡轮流发言，talkativeness/mute/自动模式，自由式多声部。
- **Persona**：用户侧角色描述，与角色卡对称。
- **Prompt Manager / 上下文模板**：用户手工排 prompt 块、instruct 模板、采样器逐聊天配置——**全部旋钮面向用户开放**。
- **STscript**：斜杠命令 DSL（/say /gen /loop/变量/闭包）——实质是 proto-agent 编程语言，社区在其上建场景脚本与小游戏。
- **扩展生态**：TTS/表情立绘/SD 绘图/视觉/翻译/QuickReply；中文社区（TavernHelper/类脑系）加 JS 执行、regex 变量追踪——**从模型输出 regex 抽数值（金钱/好感度）→存变量→渲染 HTML 状态栏回注**，在非 agent 壳里手工重建确定性状态机；Vector Storage 扩展补 embedding 检索。
- **2025-26 的 Agent 化演进**：官方 Function Calling 落地——扩展可注册工具让 LLM 调用（[文档](https://docs.sillytavern.app/for-contributors/function-calling/)），工具调用递归上限可配、interleaved thinking、DeepSeek/GLM 4.7 等工具型模型接入（[releases](https://github.com/SillyTavern/SillyTavern/releases)、[2026 评测](https://weavai.app/blog/en/2026/04/23/sillytavern-ai-roleplay-guide-setup/)）；社区 SillyTavern-Tools 在试工具集。**外挂式症状实证**：工具调用把一轮回复拆成多条碎消息（[issue #4250](https://github.com/SillyTavern/SillyTavern/issues/4250)），正按 bug 修——agency 是补丁而非执行模型的结构性摩擦。

### 诊断（酒馆范式）

调参文化（order/depth/position/probability 全暴露）不是用户爱好，是**推送式注入范式的症状**——只能靠调参抢模型注意力；社区黑客（regex 状态机、STscript 小游戏、状态栏文化）是**用户对 agent 范式能力的持续投票**——确定性状态、可验证事实、可编程编排，范式给不了就壳外自建。酒馆正以 function calling 自我改造，但中枢仍是聊天，agency 是外挂。

## 二、本项目现状（对照面盘点，2026-08-24 代码实证）

- **中枢**：作品=文件夹、章=md（frontmatter 携带元数据）、结构从标题派生可重建；对话/改写/续写/审阅是辅助通道；正文产出必经暂存提案（stage_chapter_proposal，kind=append/replace/replace_all）→ 作者批量采纳 → 落盘，直写工具带审批闸（0012 铁律）。
- **连续性**：四维账本（伏笔四态/知情/道具托管链/时钟）+ 证据锚 {chapter,line,quote} + 对账器三规则 + 确定性诊断十则 + 章切片按章确定性过滤注入（防未来泄露/降噪）；38 个 MCP 领域工具，模型可主动拉取（切片/摘要/read_style/voice_fingerprint）。
- **姿态与方案**：personas（AI 工作姿态，md）≠ 角色卡（0010 划线）；方案=通道×角色分配表（书级，pill 切换）；0015 稿：模型按用途槽进方案。
- **声口**：style.md 事实源 + 声口建档 skill + voice_fingerprint 纯计算指纹 + 续写/改写声口偏离仪表（v0.2.11）。
- **验证栈**：1011 测试 + cargo 19 + CI 门禁 + e2e 12 步（真实 LLM）+ promptfoo 行为回归（4 用例）+ 发版护栏（事务化 bump/幂等续传/签名）。
- **在排**：0015 模型方案绑定（稿）、块 4 长篇连续性阶段（4.0 定稿/4.1 地基/4.2 角色卡/4.3 补账/4.4 预警/4.5 收口）、3c 碰撞深化（挂 3a 数据）。

## 三、逐层对照

| 层 | 酒馆 | 本项目 | 判词 |
|---|---|---|---|
| 叙事中枢 | 聊天记录即作品 | 稿件文件即作品（git 友好） | 中枢选择决定一切下游差异 |
| 角色 | 角色卡=提示词容器 as artifact，分享文化强 | personas=工作姿态；角色卡=块 4 账本实体（证据锚+诊断+预算） | 「提示词 as artifact」vs「数据 as artifact」；分享文化该学 |
| 上下文 | 世界书关键词推送+全旋钮+作者注释+RAG 扩展 | 分层注入+确定性切片+模型主动拉取+预算 | 推送碰运气 vs 推拉结合；零旋钮换确定性 |
| 状态 | 核心无状态，社区 regex 自建状态机+状态栏 | 账本原生一等状态+确定性审计 | 社区黑客=agent 需求的民意证据 |
| 生成通道 | swipes 低成本横向重 roll，消息级编辑 | 暂存提案+批量采纳+审批闸 | 生产 vs 探索；swipes 该学（对 D16） |
| 多角色 | 群聊自由式多声部 | 碰撞四节结构化协议；多角色须编排（0010 修订注） | 换掉不可控，留即兴乐趣给「对戏」场景 |
| 可编程 | STscript+扩展生态广度碾压，function calling 外挂 | MCP 38 工具+skill+契约只加法 | 广度不追；深度（对账/立法）酒馆无对应物 |
| 模型接入 | 每聊天一模型，采样器全开 | 预设池+三用途槽+方案绑定+档位两轴 | 玩家面 vs 生产线；0015 后主要场景追平 |

## 四、根本分歧（一句话）

**酒馆让作者管理 AI 的注意力，本项目让账本管理事实、让作者管理方向。** 酒馆的精巧（世界书/调参/timedEffects）是约束下的最优解；本项目的确定性（对账/审计/立法）是范式换来的。酒馆 2025-26 的 function calling 化证明方向正确，外挂症状（碎消息 issue）证明中枢决定上限。

## 五、三栏结论与建议

- **可抄四件（映射到已有登记/在排）**：
  1. **swipes 式低成本重 roll**——候选卡「重 roll」入口+多版横向对比，直接富化 D16（续写 append 候选无内联对照）的解法面；
  2. **状态可见性文化**——酒馆社区状态栏证明作者爱看状态；支持「全书状态面板」缓做项提级考虑，并入「注入可见性」缺口（信任对称性）；
  3. **timedEffects 语义**（sticky 延迟退场/cooldown 冷却）——对块 4.4 预警雷达（伏笔提醒的「别吵我但别忘了我」节奏）与切片新鲜度有直接参考；
  4. **md 分享格式文化**——personas/schemes/skills 皆 md 天然可交换，将来定约定即本项目的「角色卡生态」（单作者阶段不做平台，只做导入导出约定）。
- **新启示一件**：**与角色对戏（声口试戏）**——块 4.2 角色卡落地后，借酒馆的即兴对话循环验证人物说话味道，比看指纹报告直观；候选挂块 4 后评估，不单独立项。
- **明确不抄三件**：调参面全暴露（作者=小说家不是工程师，0010 已定开放层/封存层）；自由式群聊进正文管线（多声部走结构化编排）；TTS/立绘/SD 绘图表现层（0011 明确不做 AI 绘图）。
- **护城河确认**：对账器/确定性诊断/暂存区立法/证据锚账本在酒馆生态无对应物——因为聊天中枢没有可对账的 artifact；这是「工作台中枢」的结构性优势，块 4 应加深而非稀释它。
