> 性质:0.1.6 亲测反馈 8 项 + 挂起提议 4 项的统一方案,取代 `docs/下一步方案-写作体验批与后续.md`(批一次序与零散决策并入本文)。
> 原则:涉及 UI 与结构的改动一次设计、一次实施、一次发布(0.2.0),不多次返工。

## 一、布局统一设计(先定原则,所有改动归位)

**左作者、右 AI**:左侧 = 作者私有区(结构树 + 作者笔记),右侧 = AI 区(会话/对话/工具/上下文/设置),中间 = 正文。笔记和 AI 工具物理隔离(见 §三),布局上也不再混放。

1. **右侧窄条加第 5 栏「上下文」**(aiColumns.order: session/chat/tools/context/settings,宽 300):四维账本(伏笔/道具/时钟/知情地图)同屏,数据 `/v1/tools/ledger_read`(壳只读,零耦合);开栏/手动刷新取数,空态给引导。
2. **左侧结构树底部加「作者笔记」折叠区**(可拖高调,默认收起):两个 tab——全书笔记 / 本章笔记(随当前章切,按章稳定 id 存)。存 `.novel/notes/book.md` 与 `.novel/notes/chapters/<章id>.md`。
3. **快照浏览器 = 模态**(不进栏):顶栏「快照」改为打开浏览器——`list_snapshots` 列时间/章/大小,点击 `read_snapshot` 预览,确认才还原。
4. **覆盖层宽度口径统一**:收进 theme.ts tokens——模态一档 480(审批卡/速查卡/快照浏览器),浮层一档 580(B1 候选浮层),新增覆盖层只准取档。

## 三、作者笔记(#2):AI 物理不可见(关键设计)

- 读写**只走 tauri fs 命令**(Rust 侧 `read_note`/`write_note`,路径守卫只许 `.novel/notes/` 下 .md),**不进 domain 工具集**——只要进 MCP,AI 就能读,这是唯一可靠的隔离点。
- 与上下文栏的边界:笔记=作者私房话(AI 不可见);上下文=AI 维护的账本(作者可审)。同屏互补,不合并。
- 验证:对话里让 AI 找笔记内容,应找不到。

## 四、工具结果回放(上下文记忆深化,批三)

- 现状:跨轮只回放工具摘要(名称+参数),模型看不到上次读到的内容。
- 修法:session-store 的 tool_calls 元素补 `result`(截 500 字符存),回放时按 AI SDK 的 tool-call/tool-result 成对要求组装;总预算 MAX_REPLAY_CHARS 内优先近轮;旧数据无 result 自动回退摘要(向后兼容)。
- 风险:结果回放吃字符预算,需实测调截断;写作中若 AI「忘事」不频繁,可降级为只做存储、回放后置。
