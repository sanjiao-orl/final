### 3. 与 core 的接口(现状契约)

- HTTP:`GET /health`、`/dev`(免鉴权)、`/sessions[?scope=]`、`/sessions/:id`、`/candidates[?status=&chapter=]`;`POST /tools/:name`、`/chat`(SSE)、`/rewrite`(SSE)、`/candidates`;`PATCH /candidates/:id`
- `/chat` SSE 事件:`text-delta`、`tool-call`、`tool-result`、`done`、`error`;`/rewrite`:`text-delta`、`done`、`error`
- 无协议版本号;无握手/版本校验(仅 port/token)

### 4. 现状中已有但未用/仅雏形的点

- core 有 domain MCP 五工具(structure/entities/stats)经 `/tools/:name` 代理,壳无专门 UI(entities 数据无展示)
- 会话可持久化/恢复,UI 只有下拉选择,无搜索、重命名、归档
- candidate 有 `instruction` 字段,采纳后无"为何采纳"留痕展示
- 有字数显示,无目标字数/进度条
- 工具调用只有一行文字状态,无卡片化(参数/结果就地审阅)

## 二、参考:对标工具的实现

### A 组 · 写作软件

**Scrivener**
- 布局:三栏——左 binder 文档树、中编辑器、右检视器(摘要/笔记/标签/状态/目标字数);资料素材也进 binder
- 导航:大纲视图 + 软木板(索引卡)双视图,拖拽重排章节;Scrivenings 模式把多个子文档合并为连续文本读改
- 写作:Composition Mode 全屏、打字机滚动、每文档可设字数目标
- 修订:快照(Snapshot)随时存档、可回滚

**NovelCrafter**
- 布局:左项目树(书→章→场景)+ 故事圣经(角色/设定/物品库),中编辑器,右 AI 对话侧栏(可配多家 AI 厂商)
- AI 融入:生成以「当前场景 + 设定库」为上下文;产出先落对话区,审改后可一键插入正文或替换选中段——AI 文本与正文严格分区

**Obsidian(Longform 插件)**
- 布局:左文件树/大纲、中央多窗格可拖拽分屏、右反链/属性
- 长文:Longform 把「场景」笔记按序拼成手稿,提供大纲与字数统计;标签/双链组织人物设定

**Ulysses**
- 布局:库→组树(可嵌套、智能过滤)→sheet 列表→单栏编辑器
- 写作:每篇 sheet 目标字数 + 进度条;轻量标记语法;连续滚动阅读

**iA Writer**
- 布局:单栏极简,正文限宽居中,工具栏可全隐
- 写作:专注模式(高亮当前句、其余淡化)、打字机滚动、词性语法着色;Content Blocks 按标题层级把多文档拼成一篇长文

### B 组 · AI agent 工具

**VS Code Chat view / Inline chat**
- 布局:四种递进 surface——Agents window(独立 agent 窗口)/ Chat view(侧边栏)/ Inline chat(Ctrl+I 就地)/ Quick Chat(顶部浮层)
- 产出与采纳:agent 改完文件,点选文件看 diff;Checkpoints 快照一键还原整次请求;集成靠 SCM commit/worktree 合并,AI 改动默认不进主干
- 会话:多会话并行切换不丢上下文;每会话可配 harness/权限/模型

**Cursor**
- 布局:Tab 内联建议直接浮在光标后(灰色,不打断书写);大任务走 Composer/Chat 侧栏
- 产出与采纳:Tab 整条接受,支持逐字/逐行接受;Ctrl+K 内联改写;多文件改动汇成 diff 视图,**逐块接受/拒绝**,可 Accept All/Discard All;checkpoint 快照回滚
- 会话:Composer 历史留存在侧栏,多线程并行,每线程独立上下文

**kimi-code-desktop**
- 布局:三栏——左会话列表、中聊天流、右面板(Changes/Files/Agents/Tasks 四标签收纳运行产物)
- 产出与采纳:每个工具调用一张**可展开卡片**(命令/文件读写),参数与输出就地审阅;文件差异进 Changes 面板,改动不自动落盘、可整体否决
- 进度:事件流按 session→turn→step→tool.call 组织,进度、token 用量实时可见;Agents 面板列出全部子代理;Tasks 面板列出子任务与日志
- 审批:权限分级(ask/auto/yolo),敏感动作挂起弹审批卡,允许/拒绝后继续

**Sudowrite**
- 布局:中央正文编辑器,右侧工具面板集(Brainstorm/Outline/Write/Describe/Characters)
- 产出与采纳:选中正文弹出工具菜单,产出不直接写进正文——显示在浮层/面板(改写常给多个候选),作者选择**插入或替换**;Story Bible 跨章节维护一致性

## 三、参考工具的共性做法(客观归纳,不含取舍)

1. **AI 产出与正文分区**:产出先进对话区/暂存区,显式采纳后才进正文(NovelCrafter、Sudowrite、Cursor)
2. **双通道产出**:微产出在光标处内联(灰色建议、Tab/逐行接受——Cursor Tab、VS Code Inline);大产出进面板 + diff,逐段裁决(Cursor Composer、VS Code Chat)
3. **快照/checkpoint 兜底回滚**:采纳前快照、一键还原(Scrivener Snapshot、VS Code Checkpoints、Cursor checkpoint)
4. **工具/进度可视化**:执行中的工具调用卡片化,当前在读什么、卡在哪一步可见(kimi-code-desktop 卡片流)
5. **上下文面板与正文同屏**:设定/人物/大纲在正文旁边,随当前场景注入(NovelCrafter 故事圣经、Sudowrite Story Bible)
6. **目标字数 + 进度条**(Scrivener、Ulysses)
7. **分级审批**:敏感操作弹确认卡(ask/auto/yolo,kimi-code-desktop)
