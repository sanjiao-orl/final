# 0016 · 固定端口与 CSP 收口：core sidecar 随机端口改固定端口，webview CSP 收死通配

> 2026-08-23。起因：评审 R3 缓做 D10/D11 安全对随「修复批 R4」提前收口。事实约束：Tauri 2 的 CSP 只能静态配置
> （`app.security.csp` / `devCsp`，无运行时 API，官方文档口径），而 core sidecar 端口按 0002 是每次启动内核随机分配
> （`listen(0)`）——两者不可兼得：随机端口迫 connect-src 写成 `http://127.0.0.1:*` 通配，webview 里一旦有注入残留
> （DOMPurify 是第一道闸，CSP 是兜底），兜底就放行注入内容连任意本地端口。作者定案：固定端口收死 CSP。

## 决策

1. **core 固定监听 127.0.0.1:47832**（修订 0002 的「随机端口」；token 每次启动随机的口径不变）：
   - 壳 spawn_core dev/prod 两分支均传 `--port 47832`（`lib.rs CORE_PORT` 常量）；
   - 生产 `csp` 的 connect-src 精确到 `http://127.0.0.1:47832`，全部通配删除（`ws://` 无消费方一并删；
     dev 的 vite/HMR 走 `devCsp` 单独放行 `localhost:1420`）；
   - 端口绑定失败（EADDRINUSE 等）：core 向 stdout 打单行 `{"event":"fatal","message":"端口 47832 已被占用…"}` 后退出
     （prod 下 stderr 走 inherit 在 windows 子系统不可见，故走 stdout）；壳 watch_core 识别 fatal 行，
     Starting→Failed 时带具体原因，作者看到「端口被占」而非泛泛「进程退出」；
   - 两处事实源（lib.rs CORE_PORT 与 tauri.conf.json csp）用 Rust 测试 `csp_pins_core_port` 钉死，漂移即红。
2. **裸联调通道加 DEV 门禁（D11）**：壳前端 `connectCore` 非 Tauri 分支仅限开发构建
   （`import.meta.env.DEV`），生产构建不读 query/localStorage、不弹 prompt——token 经 query 传递与 localStorage
   落盘的面在正式版收死。core 侧 `/v1/dev` 页已有 `__CORE_COMMIT__` 门禁（prod 404），两道门同向。
3. **e2e / promptfoo 自拉 core 不受影响**：不传 `--port` 仍走随机端口（无 CSP 约束的进程间通道）。

## 被否选项

- **保留随机端口 + 维持 `127.0.0.1:*` 通配**：零行为风险，但 D10 只算半收，兜底形同虚设——否。
- **运行时改 Tauri Config 注入 CSP**：Tauri 2 无公开运行时 CSP API，需 core 先就绪再建窗（启动架构重排），
  侵入过大——否（若 Tauri 未来提供运行时 CSP，可重审回随机端口）。
- **壳侧 adopt 按章号模糊解析提案目标章（D6 关联）**：move 重排后旧编号可能指向另一章，自动拣选危险——否，
  维持「找不到→红条」+ core 侧 stage 时 read_chapter 存在性校验（R4 另件）。

## 代价与重审触发

- 代价：同机双开工作台时第二个实例的 core 绑不上端口→显式报错提示（多作品并发本就是缓做项）。
- 置信度：高（单作者本地工作台，双开罕见且换来明确报错而非静默损坏）。
- 重审触发：多作品并发 / 多实例需求落地时，做端口仲裁（每实例探测空闲端口 + 动态 CSP 通道，届时再议）。

## 验证

- Rust 测试 `csp_pins_core_port`（配置防漂移）与 `state_on_core_exit_prefers_fatal_message`（fatal 原因透传）；
- 实证脚本：占住 47832 → core 打 fatal 事件退出码 1；释放 → 重启精确绑回 47832 并 ready（2026-08-23 实跑通过）。
