# 0014 · 外部审计与规划重排:编辑器联动 / 护栏批 / 对账器提前 / 模型进方案 / 校验门仪表化

> 2026-08-21。起因:作者以双视角外部审计(不看文档看实现——探查子代理全仓取证 + 主 agent 实跑 check/test 复核)评估项目距离:工程成熟度约 7/10、领域实用性约 55%;叠加作者两条现场反馈(编辑器↔AI 模态分裂,不能边码字边与 AI 互动;多 AI 诉求多次口头强调均被项目基线重置回「双档够用」)。审计元发现:文档只记胜利、口头需求从不落档,AI 取景框被基线焊死。本件把审计结论与规划修订一次定稿,后续批次按此施工,不再逐批重议。

## 前置事实(审计取证,均有代码证据)

- 自报属实:693 单测实跑全绿(文档记 692,测试数随写随变,不必追平,验收以实跑为准)、cargo 17、协议 v3 双端一致、30 工具、版本六处一致、路径守卫/鉴权/CORS/key 打码真实存在且有测试看守。
- 工程短板:无 CI;`release.mjs` 自动 commit/tag/push 无确认无 dry-run、版本六处写入非事务;`build-sidecar.mjs` 先删后拷中断损产物;esbuild 未声明进任何 package.json(靠 node_modules 提升);core/src 约 31 处、domain/src 约 29 处空 catch;`domain/src/ledger.ts` 约 1950 行单文件;无 lint/format;测试缺故障注入;30 个 MCP 工具无注册契约枚举测试。
- 编辑器↔AI 模态分裂:布局本是并排推挤,但 `App.svelte` onDocClick 点击正文即收起 AI 栏——模态是点击守卫造成的;`SelectionPopover` 浮层自足孤岛,打磨历史不进会话、浮层一关即丢;五栏互斥,上下文栏无常亮。
- 模型层真实能力被低估:预设池(N 预设各自独立 baseUrl/apiKey/model,`core/src/config.ts` scanLlmPresets)+ 三用途槽(LLM_ASSIGN_WRITING/BACKGROUND/REVIEW)早已成立,多 provider 早已可行;但 README 只写双档、0013 以「双档已覆盖」不迁 llm_router、方案被 0010/0013 限定只管通道×角色——模型维度无处绑定,作者诉求被基线反复重置。
- 领域缺口:码字日历/发布流转/平台格式复制(产品定义「复制粘贴直接用」未闭环,仅 export_txt 文件导出)/取名器/敏感词预检/导入/备份迁移/崩溃恢复/长篇性能标称——此前多项既不在待办也不在明确不做,悬浮未判。
- 文档自述偏差(对外表述勿夸大):碰撞模式=容错着色的格式协议非强校验工作流;personas=AI 工作姿态非小说角色卡;采纳留痕=候选信息展示非完整审计链;裁决留痕=md 追加行非可检索决策系统。

## 决策

1. **编辑器↔AI 联动(批一⑤,④之后立即做)**:⑤a AI 面板钉住——栏头图钉,钉住后 onDocClick 不收起,写作与 SSE 流并行;钉住状态持久化按「可配置默认否」进设置。⑤b 选区→对话桥——浮层加「带到对话」(选区作引用块进对话输入框,作者显式发起,不违正文全量注入禁令)与「转入对话打磨」(已有候选+指令历史带入章级会话,多轮留痕可回读);回流复用锚定替换候选(kind=replace),壳采纳逻辑不动。⑤c(可选)右栏闲置落上下文栏只读视图。过门:真实写作一轮,自问开合栏与上下文重述是否消失。
2. **工程护栏批(不晚于下次发布)**:release.mjs 加 dry-run + 版本写入事务化(临时副本全量写、校验过再落账);GitHub Actions CI(npm ci + check + test + cargo test;e2e 需 key 不进 CI);esbuild 声明进根 package.json。理由:693 测试无门禁等于没有保险;release 脚本是目前唯一能造成实际损失的部件。
3. **批二重排:对账器 → 章摘要 → list_trash**(修订 0011 批二序):对账器是离谱率唯一直接抓手 + 碰撞地基(0013)+ 章摘要证据锚格式上游;《我的小说》章数尚少,摘要价值随章数增长,可后移。
4. **日更手感小包(批一⑥)**:码字日历(按日落账,兼成稿速度仪表)、章发布流转(frontmatter status:草稿→已发布→已校对)、平台格式复制(export_txt 之上补剪贴板+平台格式,闭环产品定义承诺的最后一公里)。
5. **模型层:方案内模型绑定**(修订 0010/0013「方案只管通道×角色」及 0013「llm_router 不迁——双档已覆盖」的覆盖判断):方案 frontmatter 加可选 model 键,按 通道×角色 绑预设 id;解析序=方案绑定 > 用途槽 > 第一预设;persona 本体保持纯提示词,配置口子只开在方案层,守住「可配置默认否」。时机:批二之后、碰撞深化之前——同模型自碰撞=同上下文假三方的模型层翻版,真三方会审以此为前置。**作者本人修订产品定义第五轮「双模型」表述为「模型池+方案级绑定」**(产品定义允许作者本人修订,原文加修订注指向本件);README 补写预设池用法(D4 正名)。
6. **校验门仪表化**:0011 双指标此前靠体感——码字日历=成稿速度测量仪;对账器+诊断发现计数趋势=离谱率代理指标(诊断误报统计挂起项随对账器上线激活)。此后每批过门须报数不报感。
7. **弱点与需求登记制**:现状.md 新增「弱点与需求登记」节,本次审计短板全数落档;此后作者口头强调的需求/被纠正的教训,AI 有义务当场问一句「要不要登记」——防会话间被基线重置(「多 AI 诉求被反复重置」即此机制缺失的实证)。

## 缓做补判(逐个判生死,不再悬浮)

- 敏感词预检:缓做,触发=平台真实打回一次。
- 随机取名器:进 `core/prompts/candidates/` 试跑架(零工程,书级试跑转正走 0009 先例)。
- 锁屏码字(小黑屋):明确不做——与 F8 专注模式重叠。
- 导入既有作品:缓做,触发=首次需导入老书。
- 作品备份迁移:缓做,触发=单书过 10 万字或换机。
- 编辑器崩溃恢复:缓做,触发=真实丢稿事件。
- lint/format、故障注入测试、MCP 工具注册契约枚举、结构化日志:缓做,触发=CI 落地后统一评估。
