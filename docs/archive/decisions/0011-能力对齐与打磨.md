# 0011 · 新阶段：能力对齐与打磨（双轨三批）

> 2026-08-17。起因：v0.2.2 发布、批三-1/-2/-3 收口、北极星（亲写 3 章可投稿）已达成后，作者发起「小说领域 Cursor」目标的全景评审（能力地图 → 账本承载力 → 知识图谱对齐 → 实时性 → 项目拆分 → 模块升级），并要求以对抗性思维回审全部讨论。对抗性回顾推翻了初版能力地图的若干排序与立项，本决策记录最终裁定。

## 目标与校验门

- 北极星双指标：**成稿速度** 与 **离谱率**。每批发版前过校验门：这批让成稿更快了吗？让离谱更少了吗？都答「没有」的批不做。
- **显性手感轨**（用户第一天能感觉到的）与**隐性理解轨**（长期护城河）并行双轨，每期各取一件；不再按「理解层 > 生成层」串行——作者的瓶颈更可能是日更吞吐与空白页恐惧，而非 AI 离谱。

## 第 0 步：行为数据挖掘 → 作者访谈替代（2026-08-17 修订）

~~原设计：B8 采纳留痕 + issues 处置状态 + 会话超预算计数，产出三行结论校准批序。~~ 主体已被 **grill-me 作者访谈替代**：单作者产品下作者即唯一用户，问人比猜数据便宜；且采纳留痕样本窗口已被 0012/v0.2.3 重置（此前正文直写 bypass 暂存区，留痕分母残缺，算出的采纳率系统性失真）。访谈三行结论：① 主痛点是「AI 思考碰撞不足」（建议窄而传统，缺新点子与深度）；驳回主因在讨论/理解质量而非正文质量——生成是讨论的下游，**不据此上调生成层权重**；② 「误报最多的诊断规则」保留数据回看：对账器上线后自然积累，届时一次回看（访谈给不出精确值）；③ 超预算会话占比不构成当前阻塞，维持挂起。落地即为本决策批序改写（下）。

## 批次

### 批一 · 显性手感（生成层的正确形态）（2026-08-17 批序修订）

1. **批三-4 角色与方案收尾**（0010 已定稿，收编为本批第一项，机制底座先行；含两条预置 skill 的 description 改触发条件式；角色库/方案机制是碰撞模式的承载设施，故必须排其前）。
2. **碰撞模式**（新增立项，2026-08-17 访谈）：对话式思考碰撞工作流，本批首个消费者。形态：chat 内切换「碰撞」入口，复用角色预置（0010 讨论陪练角色在此落实）+ 提示词强制结构（先给 2-3 个不同方向方案 → 主动挑漏洞 → 给反直觉/极端替代方向）；零新 UI，对话区用对比色渲染区分方案/反方。目的：解决「AI 建议窄而传统、缺新点子与深度」——生成是讨论的下游，碰撞质量决定生成质量。依赖批二对账器（地基：AI 对你话与既定内容的理解）。
3. **触发式续写**：快捷键/按钮唤起（要才来），便宜档，带总开关。**起步不做 ghost-text 自动浮现**——AI 味在句中渗入是北极星红线，且作者写感不容声口污染。
4. **工具回放预算校调**（自 0009 缓做提级：500 字符对章内容偏紧，真实卡点已被多轮讨论确认）。

### 批二 · 理解层供料（全部导生/确定性，零新维护面）（2026-08-17 批序修订：对账器升级为碰撞地基）

5. **章摘要**：采纳落定时由便宜档自动生成每章摘要，存为**导生缓存**（可焚可重建，同 0004「结构从文件派生」纪律）；为语义检索/会话摘要/跨章回顾供料。**不做登记型事件流水**——手工登记作者不会做、模型登记引入新漂移面，导生化后漂移问题自动消解（重生成即可）。
6. **对账器**：账本证据锚（setups/payoffs 的 chapter:line:quote、knowledge 的 since/refs）回验正文的确定性工具，让「账本抽错」可检测可报警——理解层防漂移的核心件，成本最低价值最高。**2026-08-17 提升为碰撞模式的地基**：碰撞质量依赖 AI 对既定内容的理解，账本可信是上游（访谈结论「生成基本取决于讨论，讨论吃对既定内容的理解」）。
7. **list_trash 收口进 domain**：软删记录现由壳 localStorage 跟踪（`work.svelte.ts` 自认 domain 无此工具），换机即丢、不在事实源内，收进 domain 工具。

### 批三 · 状态登记（触发式）

8. **角色卡一等实体**（境界/修为/状态/阵营/生死/当前位置）+ **设定登记**（境界名/功法名/势力/地名等术语一致性，复用登记表模式）。触发：对账器数据或真实写作显示术语/角色状态开始失控（通常连载中后段）。

## 挂起清单（触发才动，不进版本）

- 语义索引/embedding（维持 0004/0006/0009 后置结论；触发：真实查询失败被记录——小说的交叉引用已被账本显式建模，embedding 收益存疑）。
- 会话压缩摘要层（触发：第 0 步的超预算会话占比实测超标）。
- ghost-text 行内续写（触发：触发式续写留住率达标；且必须带总开关）。
- 全书状态面板（触发：状态数据源 ≥3 个且散在多处——现 LedgerView/ReviewPanel 够用）。
- workDir 根白名单 / 工具调用 workDir 一致性拦截（触发：开始导入外部文本或多作品并发）。

## 结构纪律（本轮讨论沉淀，后续批次遵守）

- **事实源唯一**：人审内容（正文/账本/角色卡/设定）留 md，人可读可 git；机械态与导生态（章摘要/索引/回放摘要）可入 sqlite 或缓存文件——按「谁会编辑它」分流，不按「它是什么数据」分流。
- **导生物可焚可重建**；预处理走「脚本 → 导生物 → 主程序只读」。不拆仓——domain 即纯数据处理模块，MCP 缝保持随时可剥离（留待第二个消费者出现再说）。
- 26 个现有 MCP 工具契约不动，新增只做加法。
- 新增理解层维度必须同时带三件：证据锚（可回指正文）、至少一条确定性诊断、注入预算上限。缺一件即新噪音。
- 注入面维持 0010 三层（契约/姿态/数据）；批三-4 的角色注入在姿态层落位，确定性检查不被方案配置。

## 落选 / 不做（本轮对抗性回顾裁定）

- ghost-text 起步：见批一第 2 条。
- 语义索引立即上马：见挂起清单（初版能力地图曾列为缺口，对抗性回顾降权）。
- 全书自动建知识图谱（GraphRAG/LightRAG 式）：代码图谱有编译器当裁判，小说没有，抽取错误会静默污染注入。GitNexus 类理解管理系统只取形态（导生索引、查询即切片、确定性抽取优先、MCP 暴露），不取语义模型。
- 游戏式单一权威实时状态机：信息流方向相反（正文→状态，非状态→正文），且多级真相（叙述性诡计/戏剧反讽）是合法叙事手法。对账器 + 诊断分级 + 证据锚是本域的正确形态。
- 拆仓/拆项目：domain 已是纯数据处理项目，拆分只换来版本漂移与协调成本。
- 预处理操作台（用户侧）：工程概念不泄漏给作者；预处理全自动（写时/采纳时/启动时钩子）。
- 清除归档旧文档：保留历史可溯性，以 `docs/archive/README.md` 索引解决干扰。
