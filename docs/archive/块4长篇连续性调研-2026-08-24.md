**③ 摘要-账本关联字段（4.3 前半）——与 0013 决策 4 冻结语义正面相碰，须显式裁定**：机检字段「随缓存落盘即冻结、重建不回改」；新增的关联字段是冻结族还是导生族？挂摘要侧还是账本侧？初步倾向导生（链接依赖会变的账本状态，冻结必漂移），4.0 拍板；若动冻结语义，按「旧决策不重写」纪律在 0017 给 0013 记修订注。

### 2. 考古独有两个新发现

**发现一：角色卡是被「结构论证」提前拉起的，不是被原始触发器拉起的。** 0011 第 8 条原始触发=「对账器数据或真实写作显示术语/角色状态开始失控」；承载力评估的复活论据=职责面超载（schema 缺归一化、关系无承载），是结构缺口、不是失控实证。这是项目首例以结构论证而非触发器响动提前执行缓做项——合理，但调研须验证：真实写作里到底撞没撞到角色/术语失控实例？撞到→4.2 诊断先行；没撞到→schema 先行、诊断配最低菜单。直接改变 4.2 重心。

**发现二：角色状态字段的更新频率，使 4.2 与 4.3 的耦合比批序显示的深。** 现有四维=低频登记（每章几条、作者条条在意）；角色的位置/生死/境界=高频变化（每场都在动）。若 4.2 做成纯登记型、只靠 chat 引导 ledger_upsert，漏登记缺口会在角色维度放大一个量级，正撞 0011 明说的「手工登记作者不会做」。4.0 的 schema 大概率要按更新节奏分流：静态设定（阵营/外貌/关系骨架）走登记型；动态状态（位置/生死/境界）走补账提案型（扫描出提案、作者批量裁决）——即「谁会编辑它」分流纪律（0011）在字段级的应用。若成立，「4.2→4.3」批序对动态字段可能是反的（补账通道得先在）；块 4 已留「按真实写作先撞到的重排」口子。

### 外-1 · 专业写作工具的实体形态（a 线，喂 4.2；2026-08-24）

对象：NovelCrafter Codex（字段级深挖）、Campfire Writing、bibisco、Scrivener、World Anvil、LegendKeeper、Fictionary/AutoCrit/SmartEdit/ProWritingAid（检查类）。

- **外-a1 · 角色字段行业共识清单（全对象并集）**：身份（name 建议全名/aliases 绰号称号/role 主反配/tags——NovelCrafter 明确 tags 纯人用 AI 不可见）；视觉（单图头像）；外貌（发眼身高等结构项，Campfire 100+ 属性）；心理（personality/**conflict**/fear——bibisco 138 题含 psychology 组）；社会（关系/家族/职业——bibisco 单列 sociology 层）；叙事（backstory/前史 + **arc/evolution 角色变化独立一等字段**——bibisco evolution、Campfire Arcs 模块）；能力（战斗风格/武器/Game Stats——网文境界战力的字段位，Campfire Abilities）；动态（**当前位置**（World Anvil 字段+地图 pin）、**出生/死亡日期**（World Anvil 显式字段）、per-chapter 状态）。
- **外-a2 · 结构性共识三条**：①「一张自由 description + 少量结构字段」是主流，NovelCrafter 官方明确劝少建自定义字段（仅「按需注入」与「需单独强调」两种情况值得拆）；②「变化/成长」独立于静态设定建模，不塞一张卡；③**关系建模是全行业弱项**——自由画图（Campfire 单向箭头、bibisco 连线）、父子分组（NovelCrafter relations），没有一家做带类型的结构化关系边——本项目不建关系图谱与行业教训一致（红线再证）。
- **外-a3 · 别名归一谱系（弱→强五级）**：人肉多 keyword（Scrivener）→ 显式双链不扫正文（LegendKeeper/World Anvil）→ **别名表+精确词典匹配+同形词排除表+大小写开关（NovelCrafter，最工程化形态）**——默认大小写不敏感可改敏感、排除列表（角色 Will 排除助动词 will）、缩写自动区分、双面角色配方（一主名+其余身份全进 aliases）→ 导入期统计识别 cast+人工确认（Fictionary）→ 专有名词统计抓拼写变体 detect-only（SmartEdit/AutoCrit）。**中文空白**：名/字/绰号/称谓（师尊、叶家小子）到角色的映射无产品做过——英文靠大写+分词，中文必须走分词/词典+称谓规则，是本项目原生差异点。
- **外-a4 · Fictionary 先例（与补账协议同构）**：导入手稿自动扫描生成初始 Cast of Characters、自动链场景、自动设 POV，然后**要求作者先人工校对名单**再逐场景确认——「从正文反建实体库+人工裁决」的唯一量产先例（确定性统计识别、一次性导入、面向完结书稿；本项目加 LLM 提案与连载滚动为增量）。
- **外-a5 · 空白确认**：NovelCrafter 无 Continuity Checker（竞品 The Novel Kit 以「Codex 存作者意图事实、我们从导出正文提取高频词，两者 mismatch 即 review flag」打差异化——需求真实存在）；「角色卡声明状态 vs 正文实际描写」的确定性比对无工具做到；**章节粒度状态账本（第 N 章生效+证据锚）全行业无对应物**；检查类工具全部假设「写完一本书再编辑」，百万字连载滚动维护无先例。

三问过滤：改变 4.0 角色卡 schema 的字段集与分层（a1/a2）、别名机制工程形态（a3）、补账提案量产先例（a4）。前提差异——全部英文生态（大小写/复数机制不可平移中文）、云端订阅为主（本地买断仅 Scrivener/bibisco/SmartEdit）、TTRPG 奇幻权重高与网文连载权重不同、纯手工维护无提案流。红线——零冲突（a2 反向支持不建关系图谱）。

### 外-2 · 学术与 agent 长篇一致性（b 线，喂 4.3/4.2；2026-08-24）

- **外-b1 · FactTrack（NAACL 2025）：角色状态=带生效区间的事实**。流水线：新事件分解原子事实→判**有效期（validity interval）**→矛盾检测→写入并更新旧事实；核心是**区分「过期」与「矛盾」**——角色死=某章后失效，非删除。与账本时钟维天然对齐。前提/红线：英文、全自动写入、单一有效期——不支持多级真相（叙诡需「读者视角死、真相未死」双记录），须扩展知情权分层后用。
- **外-b2 · ConStory（2026）实证分布——漏记高危=时空类状态**：事实多埋于 15–30% 进度、矛盾聚集 40–60% 段、**地理与绝对时间类埋收距离最长（约 30% 篇幅）**——漏记的代价几十章后才显形，高危条目恰是角色位置/生死/境界。其检测器为四段 LLM-as-judge 带证据链（推理+引文+位置，与 {chapter,line,quote} 锚同构），注入错误验证集 **F1=0.678**（人类双标注员仅 0.281）——**提案清单必然带噪音，人工裁决层是实证必需**（补账协议与该结论互证）。
- **外-b3 · ICAT（ACL 2025）/NarrativeFactScore：双向覆盖比对**——「准确性（账本→正文）」与「覆盖度（正文→账本，即漏记）」正式化；本项目已有确定性锚验证=precision 方向，**漏记检测=recall 方向，学界做法是 LLM 原子声明抽取+与账本/摘要匹配**。NarrativeFactScore（叙事专用）从叙事与摘要**双侧**结构化对齐，区分「幻觉（错误）」与「**遗漏（缺失）**」——**摘要-账本关联字段的最接近先例**（考古问③的外部回应）。
- **外-b4 · 「扫描→提案→裁决→落账」是谱系空位**：裁决谱系三档——自主落库（MemGPT/Letta 自调工具、Mem0 ADD/UPDATE/DELETE/NOOP 自裁、A-MEM 自主重组、国内自动入库派）→ 事后人工编辑（ChatGPT/Claude memory 可查看可删改、Letta ADE）→ **事前人工裁决：查无生产级/学术级先例**。可借组件：Mem0 操作原语（**带 id 的操作序列做提案格式**——提案=对账本的可执行 diff）、Letta 行号+块权限位（**read-only/agent-editable=冻结字段 vs 可补记字段的成熟同构**）、Mem0g 失效标记不删除（多版本真相留痕；其图谱实现本身撞线，只借语义）。
- **外-b5 · 确定性 vs LLM 分工实证**：文献一致支持「确定性管已知验证与互链（高精度可复现），LLM 管未知发现与提案（高召回带噪音）」；中文小说垂直场景抽取 F1 无公开数字（明说查不到），最近似参照=英文 LLM 检查器 0.678 与临床域「LLM vs 规则」对比（LLM 召回占优/规则可复现占优）。为「确定性对账管存量+LLM 扫描管增量+作者裁决兜底」三层架构提供旁证。
- **外-b6 · 其余**：ConWriter 静态/动态双记忆与「冻结机检字段 vs 可变账本」同型，但其 forbidden effects（死亡角色不得复现）是单一权威状态机——**撞红线**，只借检查分层思想；Generative Agents 的 reflection 由**重要性累计阈值**触发（非每步强制）——可移植为补账扫描触发器；novelIDE（MIT 开源、中文、本地）伏笔卡已埋/已回收/废弃三态+闲置章数统计、AI 自动入库无裁决层——可当「无裁决版」对照实验品；LongWriter/StoryWriter 等主流长篇生成线默认「一致性交给模型」，与本项目路线相反，反衬定位。

三问过滤：改变 4.3 方法论（b2/b3/b4——噪音预期、双向比对、提案格式）、4.2 动态状态建模形态（b1 生效区间）、扫描触发器（重要性阈值）。前提差异——英文/研究 demo/全自动/云端强模型居多；NovelCrafter Progressions（状态挂时间点覆盖）为工程侧同构。红线——Mem0g 与马良（知识图谱）、ConWriter/CFPG/FactTrack 的单一真相语义撞线只借思想；ICAT/NarrativeFactScore/Letta 编辑原语/NovelCrafter mentions 不撞。

### 外-3 · 分级提醒与警报疲劳（c 线，喂 4.4；2026-08-24）

- **外-c1 · 等级绑定处置语义，不绑主观严重度**：rustc 六档的核心轴是「是否阻断/能否局部覆盖」而非「多严重」；Google「编译器不发电软警告」（要么构建失败要么进 review，纯警告必被忽略）；only-warn 插件流行（全折平为 warn，CI 边界统一 `--max-warnings=0`）证明「处置通道只有两种时，两档+类型标签优于四级主观分级」。对 4.4：**每档绑定不同动作**——保护事实被提案改动=deny 语义（直接拦 AI 提案）、伏笔逾期=warn 语义（雷达置顶）、悬空=展示语义（仅入清单）；与现有四级 severity 兼容但重新解释为处置级。
- **外-c2 · 逐条 dismiss 强制理由枚举，理由驱动后续**（GitHub code scanning 四枚举 false positive/won't fix/used in tests/mitigated；rustc `#[allow(reason)]`）：叙事工具的关键分叉——**「有意延后」必须是理由一等公民**（伏笔逾期可能正是作者计划），选后应改锚新预计卷而非反复报警。
- **外-c3 · 抑制记录要垃圾回收**：FSE 2025 首个大规模抑制研究（3 语言×4 分析器）实证 **50.8% 的抑制注解已不抑制任何警告**（抑制随代码演化腐化）；ESLint reportUnusedDisableDirectives 与 rustc `#[expect]`（预期的问题没出现反而报警）是解法。`#[expect]` 模式可移植为绊线反向：「我预期第 X 卷出现 Y——没出现时提醒我」。
- **外-c4 · 基线先行，报新增**：装雷达当天全账本会亮红灯——先拍**卷/章快照基线**（Android lint baseline 入库只报新增、SonarQube new code 通过后参考点自动前移、Google「只报新引入」），存量降为常驻清单，打断级只留新增越界。
- **外-c5 · 编辑态与验收态分离**：Android lint「编辑器实时检查忽略 baseline，批量检查才生效」——写作时 gutter/侧栏常驻（todo-tree 模式：高亮+树+计数徽章，零弹窗），发布/导出检查才全量拦截。单作者场景 deny 档必须稀少（作者绕过整个系统=止损线风险）。
- **外-c6 · 重报锚定内容坐标非时钟**：Sentry「resolved in next release」（新版本复发才 Regressed）→ 映射为**卷锚**（同一伏笔被 dismiss 后，进入新卷仍逾期或预计卷再顺延超阈值才重报）；Coverity 存续绑定（问题消失变 Absent Dismissed）。不走 GitHub 式永久不重报（账本是活的），也不走定时重弹。
- **外-c7 · 升级换通道不重复弹；处置率跟踪自动降级**：重复提醒教会用户找永久静音开关（Sentry archive forever 即逃生门）；久未处理的逾期不应提频，而应在发布检查这个唯一硬门禁升级为阻断项。**Google「有效性」定义值得照抄：作者没采取任何行动就算误报**（哪怕技术上诊断对）——新预警类型先灰度（仅清单可见），处置率高才升主动提醒，低则进 nursery（Clippy allow-by-default 晋升制）。同时回应考古问②：**0011 欠的「误报回看」可升级为处置率持续仪表**，比一次性翻日志更釜底抽薪。
- **外-c8 · 学术数字稀缺声明**：「编译器警告被忽略比例」无可靠学术数字（Kudrjavets 2022 position paper 明说实证稀缺）——4.0 不引用具体百分比，设计依据用机制性结论（上述七条）。

三问过滤：改变 4.4 的档次语义（c1）、dismiss/重报协议（c2/c3/c6）、基线与触发（c4/c5）、有效性仪表（c7）。前提差异——代码有构建/CI 硬门禁可大量用 deny，小说只有发布检查一个可阻断点且作者=验收人（过度阻断→弃用→止损线）；代码对错客观可验证，「伏笔逾期」可被叙事意图合法推翻（won't fix 一等公民）；无协作者（Tricorder 的 review 载体用发布检查替代）。红线——零冲突。
