# 审核手册（二审执行件）

> 配套 `AGENTS.md` 禁令"完成=自测+二审"两条。本件只说怎么审，不新增规则；规则膨胀即事故。
> 定位：二审是独立会话、独立证据，不是工作 agent 报告的复读。

## 何时审

- 每轮任务出口前（工作 agent 自测通过后，向作者交付前）。
- 打回项修复后复验（只验打回项+受影响面，不全量重审）。
- 周末作者亲写验收前，二审必须先过——二审不过的不浪费作者时间。

## 证据标准（只信这三样）

1. **复跑**：`npm run check` / `npm test` 当前再跑一遍，看真实输出，不看历史截图。
2. **实测**：真实链路走一遍——真实 LLM（key 见 AGENTS.md）、真实进程起停、真实浏览器/壳操作；mock 全绿不算数。
3. **独立核对**：工具/功能产出的数据，与审核人独立算出的地面真值对数（如字数独立统计、文件内容直接读）。

不采信：工作报告、文档声明、"已完成"字样、上一轮已通过的结论。

## 操作清单

1. 拿出口定义：roadmap 对应周出口 + 本轮任务范围，逐条列出，不扩不缩。
2. 复跑 `npm run check` 与 `npm test`，记录结果。
3. 真实链路实测出口路径（含**首次路径**——新会话、空状态、首次启动这类单测最少覆盖的地方）。
4. 抽查 1-2 个数据点做独立核对。
5. 出结论：通过 / 打回（打回必须列具体项+证据）。

## 打回与复验

- 打回项必须可执行、可复验（不写"质量不行"，写"X 路径下 Y 操作必现 Z 错误"）。
- 修复后复验打回项及其受影响面，通过才算完成；不接受"已修复"声明。
- 二审发现的缺陷修复后，应补回归测试（防同一缺陷二进宫）。

## 产物

- 一条结论 + 证据列表，直接回复作者，**不新增文档**；本手册是唯一审核件。
- 缺陷与修复留在代码与测试里，验收截图等临时证据放 `.playwright-mcp/` 即可。
