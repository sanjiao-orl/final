# 壳重设计 v4——调研与大型调整方案

> 性质:第四次壳调整的调研报告 + 实施方案,接「壳重设计-*」系列(v3=窄条+多栏)。
> 起因:2026-08-15 作者真实使用反馈「乍一看没问题,仔细看问题不小」。
> 调研方式:三路并行(agent 工具与写作产品前端设计 / 本壳代码级深挖 / 成熟产品 UX 模式)。

## 一、作者批评与代码级根因(路二深挖结论)

**直接回答"一个章节里是固定分 1-x 的吗"**:章号自动续(max+1),拖拽/移动后强制重排为连续第1..N章;重命名只改标题不动号;楔子/序章/番外等不参与编号。章内的"场"就是正文里的 `###` 标题,不编号、不强制,随意起。

次级问题(深挖附带,纳入打磨):滚动跟底无"已在底部才跟"判断(ChatColumn.svelte:21-26);Esc 在输入区误收面板(App.svelte:79-95);工具结果无全文查看;覆盖层宽度公式三种口径;切会话工具列表即清空;无快捷键帮助。

## 二、调研结论(路一+路三,交叉一致的才列)

1. **单层切换优于多层叠加**:VS Code 同一时刻只渲染一个侧栏视图+拖拽调宽+min/max 约束;JetBrains 可折叠成图标条。面板永不裁内容——溢出在面板内滚动,降级是"收起"不是"裁切"。
2. **工具调用默认折叠**:Cursor/Cline 把工具调用收成卡片列表,默认只显标题+状态,点击展开参数/结果;完成后长过程收敛成一行摘要。
3. **流式按块提交**:固定最小行高防跳动;仅在接近底部时自动跟随滚动,用户上翻即停;生成中有光标/占位反馈,工具执行期显示"正在调用 XX"+可停止。
4. **模型按职责分配**:Zed Agent Profiles(预设=模型+工具集)、Continue Model Roles(补全/聊天/embed 各配模型)、Claude Code 大/小模型分工——多份预设+按用途分配是成熟做法。
5. **长列表**:78+ 条上虚拟滚动;密度两档;master-detail(列表一行摘要,详情独立聚焦);过滤优先于滚动。
6. **写作手感**:正文限 55-75 字符行宽居中;行距 1.5-1.7;打字机滚动锚定;空状态给起点;渐进披露降噪(创作界面只露"写"所需)。

## 三、v4 调整方案

### D1 布局体系:单栏切换 + 拖拽调宽(根治 P1)

- 废弃多栏叠加:`ui.cols[]` → 单活动栏 `activeCol`(session/chat/tools/settings 四选一),窄条图标点击即切换;设置栏的上轮特例(openSettings/closeSettings)被通用机制吸收,删除。
- 栏宽变运行时状态(theme.ts 常量只作初始值),栏左缘加拖拽手柄,复用 TreeView.svelte:117-258 已验证的 pointer 拖拽范式;钳制 [280, 可用宽],窗口 resize 时同步收缩——**宽度即栏宽,从机制上不存在裁切**。
- 窄窗口降级:宽度不足时整栏可收成 48px 窄条(现状已有),不裁内容。
- 栏宽与活动栏持久化(localStorage),重启还原(借鉴 JetBrains)。
- 删除滚轮增减栏手势(隐藏手势,与单栏切换冲突)。

### D2 对话栏(P2/P3)

- 气泡用 `marked`(已在依赖)渲染 markdown,{@html} 输出;本地单用户 BYOK,内容来自用户自有模型,接受该信任面(在文档注明)。
- 工具 chip 堆叠 → 每条消息一行摘要:「N 个工具调用 · 查看」点击切到工具面板并定位到该消息分组;pending/running 态保留显眼指示(B6 审批可发现性不能丢)。
- 滚动跟随:仅当滚动位置接近底部(~40px)才跟随,用户上翻即停。
- Esc 在 textarea/输入态不收起面板。
- 流式体感:生成中显示闪烁光标;工具执行期显示"正在调用 XX";40ms 批次保留(0002 决策)。provider 端不流式的问题出文档说明(/v1/dev 验证法),不兜底。

### D3 工具调用面板(P4)

- 按消息(轮次)分组,组头=该轮用户消息前 20 字;组内卡片默认折叠(标题+状态+耗时)。
- 顶部:状态筛选(全部/成功/失败/待审)+ 展开全部/收起全部。
- 卡片详情结果全文查看(截断处"看全文"展开完整 JSON)。
- >100 条上分页或虚拟滚动(依赖零新增原则下先分页);密度两档可后置。

### D4 多模型预设 + 按用途分配(P5,最大决策点)

- 配置:`llm.presets[]`{id/name/baseUrl/apiKey/model} + `llm.assign`{writing/background/review → presetId};tauri 侧 AppConfig 同步,config.json 存储。
- 生效机制(**不升协议**):保存+重启 core 时,tauri 把每个预设注入为 `LLM_PRESET_<ID>_{BASE_URL,API_KEY,MODEL}` 环境变量 + `LLM_ASSIGN_<PURPOSE>=<presetId>`;core 启动时构建 preset 表,`modelForTier` 按 assign 查表。模型变更仍需重启 core(低频操作,可接受)。
- tier 接通:core 增加第三档 review(review.ts 改用),chat.send 补 tier 参数(默认 writing);壳后续给"用背景档跑"的入口。
- 设置 UI:预设列表编辑器(增删改)+ 三个用途下拉;apiKey 仍明文存本机 config.json(现状口径,面板注明)。

### D5 手感与打磨(随阶段顺带做)

- 编辑器:正文最大行宽 ~72 字符居中(超宽屏不再拉满);行距校到 1.6 区间。
- 结构树:章节点加 status 色点(draft/完成),与 Scrivener Outliner 同构。
- 空状态:对话/工具/会话栏空态各给一句引导+示例(现状已有雏形,补齐)。
- 快捷键帮助:`?` 或 Ctrl+/ 弹速查表。

### 分阶段

- **阶段一(布局与对话根治病)**:D1 + D2 + D3。验收:1024×768 与 1280×720 下任何栏不裁内容;对话 markdown 渲染、工具摘要行跳转;工具面板 78 条可过滤可展开看全文。
- **阶段二(模型体系)**:D4。验收:两套预设可存可切;writing/background/review 三档各走各的模型;重启后生效。
- **阶段三(手感)**:D5 + 次级问题清单清零。验收:对照路三 10 条设计原则逐条过。

### 明确不做(防规范膨胀)

消息排队/编辑重发、Arena 双模型对比、checkpoint 回滚、长对话压缩为新线程、Corkboard 卡片视图——记入「以后再评」,真实写作验证提出需求前不动。
