## 0. 铁律（方案成立的先决条件，审定时优先裁决）

1. **粗层不产事实锚**——只有逐章精读可写账本事实（带 evidence:{chapter,line,quote}）；粗层产物一律导生物，可焚可重建。漏登记不可自愈（现状.md 缺口①）是本条的唯一依据。
2. **漏读必有台账**——覆盖率台账记区域状态机 `未读→粗扫→精读→已核销`，外加 `疑点(重开)`；地图必须诚实，未覆盖的部分显式存在、可查询、可排期。
3. **事件=导生层**——包含树与指引链可焚可重建，节点带锚指向账本事实与章节区间；图永不为源（0011）。
4. **修复过闸**——精读升级后的核销需复核（邻域再抽一根，或确定性交叉验证：触发修正的事实确实进了索引）。

既有红线全程生效：0011（确定性诊断+证据锚+LLM 提案作者裁决）、0012（正文经暂存、账本经 upsert）、0004（索引接口预留、导生可焚）、酒馆三不抄；语料不进仓不分发（`.bench/` gitignored）。

## 1. 金字塔分层（读取结构）

- **L0 确定性信号层（零 LLM）**：结构树卷边界、场景断裂、name-census 人物在场分布（诡秘全本已跑）、字数/密度离群、伏笔嫌疑句式——产出候选边界与密度地图。职责边界：确定性工具定骨架，LLM 只填语义（0011）。
- **L1 纲要层（便宜模型）**：卷摘要 → 弧线 → 事件骨架粗稿（自顶先验）。量级：几十次调用。
- **L2 事件平铺层**：簇内平铺挖事件，每事件 `{标题, 章节区间锚, 参与者, 一句话梗概}`。
- **L3 需求驱动精读层**：对每个事件过「信息需求清单」——在场人物此刻状态/知情、在场设定规则、相关道具、未兑现承诺、从上一事件到本事件的因果桥——缺什么读什么。主动寻找**复用产品工具链**（search_content / read_chapter / ledger_slice），本质是写作彩排：导入期是干跑，写作期是实跑，同一张清单两处消费（干跑数字兼作冷读预算闸的分配依据）。
- 归并层：卷/弧摘要 reduce。

## 2. 事件包含树与指引链（结构层）

- **层级由包含关系推导，不由分档判定**：大事件=容纳若干子事件的节点，小事件=叶子；大/中/小仅作展示标签，机制消费**排序**（比较判断比绝对分档稳定，绝对漂移在排序里抵消，预算松紧自动伸缩、优雅降级）。
- **两方向对撞**：自顶（L1 纲要骨架）× 自底（L2 平铺事件）互认领；认领不上的、容器与叶子对不齐的，即疑点、即反馈回路触发。两个方向的误差互相暴露。
- **关系切分（必须二分，否则图成环）**：
  - **包含**（部分-整体）：尊重叙事时间，父章节区间必须罩住子区间——因此**确定性可校验**（区间覆盖 / 兄弟不重叠 / 无环 / 每章有归属路径）。包含定义树与层级权重。
  - **指引**（埋设-兑现 / 因果）：天然跨时间（第 5 章埋、第 800 章收），是横跨树的链，不定义层级，定义**承重系数**——被后续事件引用越多越承重，值得更高精度。指引链的机器可读形态 = 账本 promises 维度的图形态（伏笔 = 埋设→兑现有向边）。
- **注意力公式**：`层级权重（树位置）× 承重系数（链度数）× 检测器加成（反馈回路）`——三个来源、一张优先队列、一个预算。

## 3. 反馈回路（质量控制）

- **快环（实例级区域状态机）**，四类检测器、确定性优先：
  1. 抽查差值——抽样深读发现账本外新事实（主通道）；
  2. 确定性异常——某角色在某区域高频在场却无任何事件节点引用（有 presence 无 event = 嫌疑空洞）、密度离群、嫌疑句式落未精读区（零成本常开）；
  3. 下游消费失败——彩排某事件时信息需求清单补不齐（用时才发现没读过）；
  4. 对账命中——矛盾扫描在该区域开火，多半意味着局部模型错误。
- **修复阶梯**：局部精读（默认）→ 邻域扩散（事实长在上下文里，带前后章）→ 确定性补扫（便宜先行）→ **挂账疑点进报告**（预算不足时的正路：一个未修复的嫌疑显式存在，好过静默声称覆盖）。
- 模式同构 bugs.md 生命周期（入账→核销→留过程）——把治理缺陷的既有模式搬到治理覆盖率。
- **慢环（策略级）**：快环核销记录聚合漏检率（按检测器 / 按卷 / 按密度档），持续偏高即调全局参数（簇粒度、抽查率、粗筛提示词）重跑受影响通道。快环修本书，慢环修流程。
- **抽查分层抽样**：按卷、按密度档、按「离任何事件最长的未触及段」各设配额——纯随机会漏探盲区。抽查差值同时是需求驱动管线的召回率度量（分子分母现成）。

## 5. 成本估算（量级参考，全部待数字修正）

- 均匀深读净本 1137 章 ≈ 2300 次深调用 + 矛盾窗口 ≈ 230 次（v0 口径 1393 章 / 2800 / 280 为历史对照）。
- 分层管线：L1 ≈ 几十 + L2 ≈ 150–300（便宜模型小输出）+ L3 ≈ 400–600（前 30–40% 事件需求驱动，事件间共享读段）+ 抽查 ≈ 70 + 归并 ≈ 50 → 深调用砍约 70–80%。
- 精度论点（不只是省钱）：均匀抽付的实测失效模式恰是 over-extraction（shakedown 收紧前 28.7 条/章，收紧后 16.2——初测件读数；噪音淹没信号）；需求驱动把钱花在「将被消费」的信息上，精读预算本身是精度仪器。
- **对照判据（0905 审查补显式化）**：四项对比（密度与精度/事实召回/失控检出率/成本）的通过与退回由作者对照数字裁决；判据框架=召回损失与成本节省的交换比 + 失控实证检出率不降（含目录 v0 实锤 4 条必须检出）——被否选项⑤的复活条件即此判据的反面，机械可执行。

## 6. 技术路线备选（竞品调研与技术谱系，2026-08-30 查证）

- **竞品三条路（均不做逐章验证性蒸馏）**：Sudowrite=导入自动填静态 Story Bible + 2 万词滚动窗（词条静态、不追状态变化，社区仍在要自动更新）；NovelCrafter=Codex 词条 + 按提及触发注入（无 embedding）；国内派（蛙趣拼文 / 马良写作 / 唐库 / Long-Novel-GPT 等）=切块 embedding RAG + 滚动摘要 + 风格词句提取。共性：质量口径是「聊天里看起来记得」，无证据锚、无对账、沉默失真不可见；云服务成本转嫁订阅费。结论：逐章状态账本全行业仍无对应物（0017 外-a5 同证），本件填的是品类空位——竞品不是更先进，是质量口径更宽松、成本结构不同。
- **候选技术（挂触发、不预建）**：
  - embedding 语义索引（缓做既有项）：指引链的跨书埋设-兑现匹配是正式触发场景（纯 LLM 配对平方级灾难 → 向量粗配 + LLM 确认）；本地模型（bge-m3 类）零额度、一次性离线。触发：指引链挖掘开工，或检索失败率超标（缓做原文触发条件在此天然满足）。
  - RAPTOR 层次摘要树：章摘要结构天然是其骨架，L1 归并按此形态。
  - GraphRAG / Graphiti（0017 已点名仅作导生层参照）：社区摘要 ≈ 弧节点，时态边 ≈ 区间。
  - Contextual Retrieval（块级上下文注释后向量化）：embedding 启动时的增强项。
  - 长上下文整本吞（中体量书可行）：无锚无验证，不作主路线，可作对照组变体。
- 明确不用：知识图谱作事实源（0011）、游戏式状态机、酒馆三不抄。

## 7. 不确定性与灵感记录（待试车台数字 / 作者裁定）

- 包含树的区间校验在多视角/闪回重灾区（诡秘即多线）的失败率未知——失败率本身列为测量项；若高企，退化方案为「弧级为顶层、卷只作分组」。
- 指引链召回未验证：埋设期候选标注的查全、兑现期匹配的查准，都靠抽查差值标定。
- LLM 粗筛质量下限未测：免费档模型差异、长簇摘要走样率；L1/L2 可能需要阶梯模型策略（便宜跑量 + 关键段贵模型复核）。
- L3 事件间共享读段的缓存粒度未设计（一次精读服务多个事件的信息需求）——直接影响实际调用数，待 L3 试跑定。
- 覆盖率台账落盘形态未定（md / sqlite）；倾向导生物目录（可焚），与 0004 索引接口预留对齐。
- 灵感留档（不承诺）：事件树 → 壳内导航与全书状态面板素材（0017 视图层候选）；大事件 = 预警雷达检查点（4.4）；干跑清单 = 冷读预算闸分配依据（4.1）；指引链 = 漏登记扫描提案（4.3）的候选证据源。
- **被否选项逐条**（防复活）：①按绝对分档分配注意力（会漂，已由排序分配替代）；②指引关系入树（成环，已切分为横链）；③抽查纯随机（盲区漏检，已分层）；④粗层直接写账本事实（漏登记不可自愈，铁律 1 否）；⑤「维持均匀深读、只调抽取密度」——保留为活候选而非死案：若对照实验显示召回损失大于成本节省的价值，或区间校验失败率高企，则退回此案。
