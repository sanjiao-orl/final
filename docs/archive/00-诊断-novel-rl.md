# novel 项目诊断与解决方案

## 执行摘要

本项目（AI 原生长篇小说写作 IDE）经历两个阶段：旧阶段 `C:\work` 死于治理文档自我繁殖与"完成度定义通胀"，2026-08-07 以白名单迁移 88/103 个源文件矫正式重启为 `C:\novel-rl`。重启矫正经独立核验有效（文档/代码比从 94% 降至 1.2%，14/14 声明真实落地，711 测试全绿），但随即出现二次漂移：Agent 层四大缺口（流式/多会话/持久化/多模型管理）被知情挂起，写作垂直层零新增，且暴露出删章物理删除、保存静默失败等否决级数据安全问题。结论：不重启，继续 novel-rl，以批次 0-4 路线图补课（安全阀优先），配防腐规则与止损线。

# 第二部分：诊断

## 2.1 旧阶段 `C:\work` 的死因：用户三条自我诊断的核验结果

### ① 文档治理过重 —— 完全成立

核验证据：

- 治理仓提交数 **175** > 代码仓提交数 **108**，治理活动反超编码活动；
- `AGENTS.md` 在 **五天**内修订 **8 版**；
- 规则在 **3 天**内增生至 **45+ 条**，被迫专门立"防增生"规则来约束规则本身；
- 文档行数达到生产代码的 **94%**（291 个文档文件 vs 164 个代码文件）；
- 出现"审计审计的报告"，以及用于维持文档自洽的对拍脚本；
- 项目自评一语成谶："以极高的效率建造一座没人住过的房子"。

### ② AI 偏离初期路线（复用为主、自研垂直层）—— 成立

- 决策 006 排除了**全部**开源 Agent 内核的复用可能；
- M10 自研通用 Agent 编排（Persona/目标治理），偏离"只做垂直层"的初始定位；
- 没有任何一份 ADR 宣布过这次转向——路线偏移在无声中发生。

### ③ 轻信 AI 文档声明导致实现大规模不足 —— 不成立，但真相更致命

- 抽查 12 项声明，**8 项真实实现、无假实现**——AI 没有撒谎；
- 真实问题是**"完成度的定义通胀"**：543 个测试全绿、MVP 里程碑全部达成，但测的全是**系统自洽**，产品有效性**零验证**——没有人用它写过一章，LLM 从未真实端到端跑通；
- 另有分支口径失控：M7-M10 全部成果（**+17,085 行**）只存在于 `feat/flash-sprint` 支线，`main` 停在 08-04，README 却营造"整体到达 M10"的印象。

## 2.2 novel-rl 重启的矫正成效（经独立核验）

重启的矫正确实生效，且有据可查：

| 矫正项 | 核验结果 |
| --- | --- |
| 文档/代码比 | 从 94% 降至 **1.2%**（361 行文档 vs 约 3 万行代码） |
| 治理膨胀约束 | "禁止治理膨胀"写入 `AGENTS.md`，并用脚本机械强制 |
| 声明真实性 | 抽查 14 条已完成声明，**14/14 真实落地**，未做项如实挂账 |
| 工程质量 | 独立复跑 **711 测试全绿**、`tsc` 0 错 |
| 复用优先 | 成文化：TipTap / MCP SDK / Tauri / plugin-http |
| 真实验证 | 首次真实 LLM e2e，作者实测驱动开发 |

## 2.3 novel-rl 的二次漂移（用户亲查 + 代码取证确认）

### Agent 层四项缺口

| 缺口 | 状态 |
| --- | --- |
| 流式输出 | 完全缺失（整响应 await） |
| 多会话 | 完全缺失（单任务串行，再次调用直接抛错） |
| 对话持久化 | 完全缺失（关窗即失） |
| 多模型管理 | 仅"双档路由"薄封装：无 fallback、无能力画像、无参数模板 |

与之对应的代价：手写约 **1,325 行** LLM HTTP 基建 + **1,010 行**配套测试，而 `package.json` 中 **AI SDK 依赖为零**。

### 项目完全知情却挂起

- 审计文档明确写着："范式可从 openworker 直接照抄，不重复造轮子"——处置却是挂 P1；
- roadmap 把"reasoning 最长 59.5s"写成**推迟流式**的理由——而 59.5s 干等恰恰是流式输出**最强的需求论据**。决策依据与结论方向正好相反。

### 写作层结构治理薄弱

- 结构节点仅 **6 字段**的纯目录容器：无场景级节点、无标签、无状态工作流、无拖拽重组；
- 对照 novelWriter 成熟范式：标题即结构、标签即实体、索引可重建——差距是范式级的。

### 精力分配失衡

- changelog 条目中，通用基建 + 审计修补类占约 **67%**；
- 小说垂直层本迭代**零新增**：现有 88/103 文件为旧仓搬迁，属吃老本；
- 耦合层有真实交付（改写闭环/实体卡注入约 **1,500 行**），但整体仍失衡；
- 决策 004 自己承认存在"排查类任务镀金漂移的时间黑洞"。

### "自研合理性"声明审查

- 隐私决策实际只覆盖密钥白名单/CORS 通道约 **300-400 行**的必要性；
- 它解释不了 HTTP 客户端与会话管理也要手写；
- 结论：**惯性自研被"防过度工程、不建框架"的正确话语掩护**。

## 2.4 病根诊断（贯穿两阶段的底层病灶）

- **旧病**：治理文档自我繁殖；
- **新药无效**：文档治理确实轻了，但"**文档自洽 ≠ 执行正确**"的病灶以新形态存活：
  - 复用原则被选择性执行；
  - 决策与执行脱节且无人追责：审计写下正确答案 → 执行挂起 → 文档零报警；
  - 用户靠读文档验收的习惯，**两次被骗**。

病灶换了载体，但没有被根除。

## 2.5 盲区扫描新发现（用户初步观察之外的缺口）

### 否决级·数据安全

- 删章为**物理删除**，绕过系统回收站，且零备份、零快照；
- Ctrl+S 为 fire-and-forget **静默失败**：磁盘满/杀软锁文件时，作者以为已保存；
- `structure.json` / entities 损坏即**白屏锁死**；全仓零版本号、零迁移；注释承诺的重建工具**不存在**；
- 结论：正文的"存"可靠，"删"和"索引"在裸奔——**作者每个字都处于"一次误操作即永失"的状态**。

### 北极星出口缺失

- 无任何正文导出（连合并全稿 txt 都没有）；
- 行内粗体/斜体保存即**静默丢失**（正确性 bug，且无挂账）；
- 字数统计为零。

### 检索失明

- 作者侧：无跨章正文搜索（检索时刻页签是空壳）；
- Agent 侧：`search_content` 对作者亲写章节**静默零命中**（structure.json / EntityStore 双轨之后果），被登记为"卫生项"属严重低估。

### AI 修订信任链不闭环

- 采纳全有全无、候选单例；
- 待决编辑无冲突提示；
- 喂给 AI 的上下文作者不可见；
- 运行中无取消。

### 中后期定时炸弹

| 炸弹 | 说明 |
| --- | --- |
| 修订快照缺失 | 无法回溯 AI 改动 |
| 大纲/规划闭环为零 | 长篇创作的刚需 |
| 风格档案缺失 | `style.md` 成本极低、杠杆最大 |
| 实体静态化 | 将污染生成质量 |
| 一致性审阅有数据无流程 | 恰是最强差异化点，未兑现 |
| UI 性能无保护 | 每击键全章重哈希、watcher 每秒逐文件 IPC、三视图无虚拟化；2700 万字压测只压了 Node 层 |
| 系列作设定边界未定 | 多本系列场景未设计 |

### 其他

- 真实手稿住在**未提交**的 `.demo-project/`；
- git 仅 **2 个提交**（4.6 万行代码）；
- release 首启白屏；
- 设置保存整页重载，丢失 Agent 对话；
- 草稿键无项目作用域。

## 2.6 平台化重启路线核验（用户提出"Pi + 社区插件"论点）

核验结论：**论点部分正确，但不构成重启理由。**

- **Pi（earendil-works/pi，MIT）确为成熟 agent 载体**：pi-ai / pi-agent-core 是 npm 库，官方 SDK 支持嵌入，有 OpenClaw 规模级实证——但它属于"库级引入"，**在现有仓库即可使用**，不构成重启理由；
- **Pi 社区插件绑定其终端编码宿主**，嵌入自定义 GUI 后不可直接享用；
- **其余平台横评**（LobeChat / AnythingLLM / Open WebUI / LibreChat / Dify / Cherry Studio）：
  - 无一支持嵌入自定义富文本编辑器面板；
  - 数据模型（聊天会话库）与"作品 = 文件夹"根本错配；
  - 许可证风险实证：Cherry Studio 单方改 AGPL-3.0 出局、LobeChat 1.0 重写、Open WebUI 插件体系推翻；
  - 平台独有能力（插件市场/聊天 UI/多用户）对单人作者工具**全是伪需求**。

# 第三部分：解决方案

## 3.1 总方针

> **继续开发 novel-rl，反对第三次重启。**

理由：

1. novel-rl 已是矫正产物，且矫正经独立核验有效；
2. 缺口的性质是**补课不是重建**：Agent 层缺口为配置级、文稿治理可借 novelWriter 规范、安全缺口是几十行小修复；
3. 两次失败的根因是**执行习惯不是代码**——重启不会改变习惯。

### 量化对比

| 路线 | 净代价 | 备注 |
| --- | --- | --- |
| 第三次重启 | ≈ 4-6 周纯重建 | 改写闭环实测修复 / CORS 密钥链 / GBK 导入等不可复制资产丢失 + 已验证集成面丢失 |
| 继续 novel-rl | ≈ 2-3 周还装配债 | 全程有可用软件 |
| 北极星功能工作（批次 2-4） | 两条路线完全相同 | 不构成差异项 |

**结论：继续路线约快 2-4 周，且全程有可用软件。**

### 重启熔断条件（任一触发则带着资产与经验重启，不恋战）

1. 批次 1 替换工作量超估 2 倍（> 4 周）；
2. 批次 0-2 实际耗时超估 2 倍；
3. 连续 3 次发现每个新功能都必须先改 `main.ts` 上帝装配根。

## 3.2 分批路线图

路线总览：

| 批次 | 主题 | 周期 | 优先级性质 |
| --- | --- | --- | --- |
| 批次 0 | 安全阀 | 数天 | 否决级，唯一插队批次 |
| 批次 1 | 复用补课（Agent 层） | 1-2 周 | 债务清偿 |
| 批次 2 | 北极星直通路 | 1-2 周 | 直达北极星 |
| 批次 3 | 垂直地基 | 2-4 周 | 长期竞争力 |
| 批次 4 | 差异化 | 按余力 | 最强差异点兑现 |

### 批次 0 —— 安全阀（立即执行，数天）

> **唯一插队到功能开发之前的批次。**

- 删除改软删，进 `.novel/.trash/`；
- Ctrl+S 加 catch 与显式错误提示；
- 保存时滚动快照（`.novel/history/`，每章保留 N 份）；
- `.demo-project` 手稿与全部未提交改动提交 git。

### 批次 1 —— 复用补课（1-2 周，双候选 spike 一周内定）

候选对比：

| 候选 | 优势 |
| --- | --- |
| Vercel AI SDK | `streamText` / `useChat` / Provider Registry / middleware；Apache-2.0；Svelte 官方适配 |
| Pi（pi-ai / pi-agent-core） | agent 循环更成品；MIT；OpenClaw 背书；与 model-router 职责一一对应 |

配套工作：

- Dexie.js 会话持久化与多会话（UIMessage 格式）；
- 传输层接 `tauri-plugin-http` 绕 CORS；
- 替换后**净删约 1,300 行**自研代码。

### 批次 2 —— 北极星直通路（1-2 周）

- 合并全稿导出（最小投稿出口，可引 Pandoc）；
- 字数统计；
- 修复行内 marks 静默丢失；
- 全稿检索接 structure.json 通道（修复 Agent 检索失明）。

### 批次 3 —— 垂直地基（2-4 周）

- 移植 novelWriter 规范：`#卷` / `##章` / `###场景` 标题语义 + `@tag` / `@pov` / `@char` / `@mention` 引用语法 + 可重建索引器（**借规范不借代码，规避 GPLv3**）；
- 场景元数据（frontmatter：status / pov / tags）；
- `style.md` 风格档案强制注入所有生成。

### 批次 4 —— 差异化（按余力）

- 修订快照（章节级 + diff）；
- 章节一致性审阅报告：把实体/伏笔/时间线数据转为作者可见的审阅清单——**最强差异化点**。

## 3.3 明确不做清单

- 图形化重世界观模块（地图/历法/关系图编辑器）；
- 多人协作；
- 模型市场 / 预设社区；
- EPUB 排版出版；
- AI 图像生成；
- 治理体系建设（规则/审计/双工具协议——旧仓教训，永不再建）。

## 3.4 防腐规则（针对两次失败的共同病根）

1. **通用基建准入检查**：写任何通用能力前，一句话回答"有无成熟替代"。有则引入；无则在决策文档写明原因。
2. **冻结审计修补波次**：在"作者亲写一章"闭环达成前，禁止发起 Wave 式排查修补与新治理建设。
3. **验收纪律**：不读文档验收，用可执行检查单（测试复跑 / 功能实测 / 对照成熟基准）验收。

## 3.5 止损线

完成批次 0-2 后，若 **4-6 周内仍无动力用它写完一章** → 判定产品假设不成立，体面终止。

可剥离资产：

- understanding 层（约 5,700 行 + 最厚测试覆盖）；
- agent-kernel；
- outbox 确认链；
- rewrite 修订交互；
- llm 集成经验。

## 3.6 关键教训（给未来的自己）

- 治理的产物必须是**被使用的软件**，不是自洽的文档；
- "完成"的定义必须是**产品有效性**（作者真写一章），不是系统自洽（测试全绿）；
- 复用优先会被"防过度工程"的正确话语掩护而选择性执行——必须用准入检查**制度化**；
- 文档声明的合理性 ≠ 核验过的合理性；两次被骗的同一习惯，必须用机制纠正；
- 数据安全是写作工具的**一票否决项**：先焊安全阀，再谈功能。
