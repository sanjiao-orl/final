## 二、现状事实(已核对的,可直接引用)

### 1. 架构

- harness+壳:`core/`=Node sidecar 核心(AI SDK v7 + MCP client + node:sqlite 会话 + 127.0.0.1 HTTP/SSE);`domain/`=MCP 领域服务(stdio);`shell/`=Tauri 2 + Svelte 5 + TipTap
- 技术路线已定不变,本次是**壳整体重做**,能力原生级设计

### 2. 壳现状组件(均 `shell/src/`)

| 组件 | 职责要点 |
| --- | --- |
| `Toolbar.svelte`(135 行) | 顶栏 42px:作品名/当前章+脏点/保存/导出/删除/暂存 badge/打字机/明暗/专注/AI |
| `TreeView.svelte`(131 行) | 左树 260px,卷→章→场三级,数据来自 `list_structure`(壳不推导);状态点+字数;软删;**无拖拽/搜索/大纲** |
| `Editor.svelte`(391 行) | TipTap(StarterKit);HTML↔md 桥;打字机滚动锁 42%;选区浮动条;场景跳转按标题文本定位 |
| `AiPanel.svelte`(230 行) | AI 对话:无归属/本章双 tab;会话下拉;消息气泡+工具状态行;composer |
| `StagingDrawer.svelte`(250 行) | 暂存抽屉(≤40% 高):全选/采纳/整改/丢弃;instruction+原文删除线/新文建议色 |
| `suggest.ts`/`pm-search.ts` | 内联装饰插件(删除线+建议色+采纳/丢弃钮);文本唯一定位 |

| stores | `work`/`chat`/`candidates`/`ui` |

### 3. core 契约(现状,重做时将版本化)

- HTTP:`GET /health`、`/dev`(免鉴权)、`/sessions[?scope=]`、`/sessions/:id`、`/candidates[?status=&chapter=]`;`POST /tools/:name`、`/chat`(SSE)、`/rewrite`(SSE)、`/candidates`;`PATCH /candidates/:id`
- `/chat` SSE 事件:`text-delta`、`tool-call`、`tool-result`、`done`、`error`;`/rewrite`:`text-delta`、`done`、`error`
- 无协议版本号、无握手校验(仅 port/token)

### 4. domain 工具(现状七个,重做将新增)

`list_structure` / `read_chapter` / `write_chapter` / `search_content` / `word_count` / `delete_chapter`(软删)/ `export_txt`

### 5. 数据模型(核心约束)

- 作品 = 文件夹;`manuscript/` 下卷=目录、章=md 文件;场=`###` 标题
- 章文件命名:`第X章·标题.md`,frontmatter `title` 与文件名一致(现状字段:`title/status/pov/tags/synopsis`)
- 卷目录命名:`第一卷·风起` 样式
- 顺序真相 = 文件名 + frontmatter title;结构树从文件派生,**可全量重建**
- 会话库 `.novel/sessions.sqlite`(core 持有);快照 `.novel/history/`;软删 `.novel/trash/`

### 6. 视觉基调(theme.ts,原型延续)

纸色 `#FAF7F0`/`#26241F`;思源宋体 17px/行高 1.75/段首缩进 2em/行长 ≤38 字;UI 禁等宽;打字机比例 42%(改字号需同步,`Editor.svelte:276-278` 注释)

## 三、已定需求决策(2026-08-10 作者定案,不得推翻)

### 总纲

1. 技术路线不变(Tauri 2 + Svelte 5 + TipTap),壳**整体重做**,能力原生级设计
2. 壳正式承担交互产品逻辑(会话/拖拽/暂存裁决/审批等),系统化设计;core 只管领域能力
3. 流程:高保真原型 → 作者+守门 AI 双审 → 定型 → 实现 → 作者亲测 → 同意才算成功

### A 组 · 章节/卷管理

| # | 决策 |
| --- | --- |
| A1 | domain 新增工具(create 章/卷)+ 壳 UI;新建章自动接续卷内编号,生成 frontmatter 模板(与 read/write/delete 契约对齐) |

## 六、沟通机制

- 需求守门 AI(本会话)负责:提供现状事实核对(源码/契约/数据模型)、确保设计不偏离已定决策、解答设计方疑问

- 任何新需求的提出与旧决策的修改,一律经作者确认
