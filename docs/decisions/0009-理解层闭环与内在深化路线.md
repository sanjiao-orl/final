# 0009 · 理解层闭环与内在深化路线（批三）

> 2026-08-17。起因:P3 规划时作者追问「四维账本层级结构与功能弱、内联理解层怎么实现的」,经主 agent 亲读 `domain/src/ledger.ts` 全文 + 三路并行深挖（管道实现/规划 vs 现状/壳侧呈现）取证定稿。作者裁定方向并补充:**账本表现形式要跟上更深的层级结构与内联关联**。

## 现状判断（证据见各行号）

- 当前理解层只有三条「按需拉取」链，**内联不存在**：冷读链（ledger_slice→/v1/review→findings)、chat 链（零作品理解注入，scope/workDir/tier 而已）、壳呈现链（静态全书账本，手动刷新）。
- S1 闭环断裂：findings 不落盘、无 chapter/line 定位（review.ts);issues.md 无代码生产者而 BLOCKER 计数靠读它（ledger.ts:1054)；壳侧 findings 内存态、无处置状态。
- S2 账本表达力平：伏笔无卷级作用域、知情维无时间轴、四维零跨维引用、无人物/设定实体。
- S3 诊断 5 条硬编码 if、永不产 BLOCKER；知情/时钟跨章连续性零规则。
- S4 账本正文「可读不可写」：手改渲染视图被下次 upsert 静默抹掉（parse 只读 frontmatter)。
- S5 声口档案缺席：00-诊断 style.md「成本极低杠杆最大」+ 写作 skill 调研（风格建模方向）双来源背书（调研原文 `docs/archive/写作skill调研-2026-08-14.md`)。

## 决策

**批三切三小批，顺序动工，每批以真实写作验证收尾。**

### 批三-1 · 闭环接通（数据层）

1. domain 加 `issue_append` / `issue_set_status` 工具（白名单 editorial_notes/ 下同账本纪律）;`/v1/review` 解析出 findings 后由 **core 确定性经 MCP 追加进 issues.md**（不靠模型自觉）。quote→行号由 domain 在章正文确定性定位。
2. CR 行格式尾部加 **status 列**(open/done/known，缺省 open；旧行无此列视为 open);`countBlockers` 只数 open 的 BLOCKER——「清零」语义 = 处置后不计。壳 ReviewPanel 加处置动作（待处理/已处理/已知），持久化在 issues.md 行内，不另起状态文件（防双写源）。
3. 注入面校订：cold-read.md 输出要求改写为 JSON 契约（删掉「追加 issues.md/更新账本」这类机制上不可执行的残留指令）;severity 统一四级 BLOCKER/MAJOR/MODERATE/MINOR,review schema 加 MINOR 与可选 category;`ledger.ts` 兜底契约串同步（消除文件与兜底双写漂移）;chat.md 补工作流指引（暂存区铁律、工具使用次序、审批流存在）。
4. 账本渲染正文加「机器渲染勿手改，要改请改 YAML frontmatter 或用工具」醒目警告；frontmatter 唯一权威态不动摇，**不做双向解析**。
5. 捎带审计清零：裸联调 token 改 localStorage 粘贴；CORS 白名单收窄（先实测壳 Origin，行不通记档放弃）；壳侧目录约定/审批去重键收 `shell/src/lib/paths.ts`。

### 批三-2 · 账本表达力（数据模型重建收尾）

1. 结构深化：伏笔加卷级作用域（预计回收卷）;知情维加时间轴（截至章）;YAML 向后兼容（normalizeLedger 容错 + extra 透传现成）。
2. **表现形式跟上**（作者补充）：渲染视图随结构升级——按卷/状态分层聚合（HOT 伏笔、悬空/逾期前置）、时钟与知情时间轴化展示、跨维引用内联（伏笔挂道具/角色、知情回指伏笔 id);`renderLedgerMarkdown` 纯派生态重写，frontmatter 权威态不变。注意：该渲染同时是冷读注入的账本切片，格式升级直接提升 AI 可读性。
3. 诊断补强：时钟跨章连续性（storyDay 倒退）、托管链断裂、知情维首条规则（secret 而 knownBy 空）；复核哪些该升 BLOCKER。
4. review 改 `generateObject` 结构化输出（生态调研「最确定的一步」)，踢掉剥围栏 hack;findings 带 chapter/line/category 直供闭环。

### 批三-3 · 内联注入

1. **声口建档 skill**：从已有章节蒸馏 `.novel/style.md`(methodology 借 writing-dna 六层蒸馏思路、证据回指借 writing-agent 账本思路，纯文本零依赖）;chat/rewrite 注入其摘要。先书级 `.novel/skills/` 试跑，真实写作留住才转正预置。
2. chat 内联：scope=章 时自动注入该章相关账本切片（伏笔/知情按章过滤，不注全账本）。
3. 上下文栏随章联动 + 三张登记表渲染 + 切章自动刷新；暂存区采纳后提示账本更新/重跑诊断。
4. 章节起草 skill 候备（流程前半段缺口，写作反馈驱动）;细纲拆分/讨论陪练再后。

### skill 决策修订（改写 0008 第 5 条与约束）

- 预置**无数量硬顶**（原「≤3」理由不成立：skill 正文不进系统提示，固定税只有一行 description)；每个预置须先在书级试跑、真实写作验证留住才转正。
- 现有两预置维持：去AI味润色（经 shuorenhua 全文对照确认为网文场景最优，不替换不合并）、章节体检。
- 候选序：声口建档 → 章节起草 → 细纲拆分/讨论陪练；一次只试一个。

### P3 处置记档

- 缓做（配触发条件）:skill 管理 UI（触发：skill 多到管不过来）、回放字符预算校调（触发：写作中模型上下文不足）、promptfoo 回归（触发：prompt 迭代需要防回归时，生态调研建议项）。
- 不做：壳内指令模板搬家（实查仅 3 个短串，属 UI 文案层，搬家收益不抵壳↔core 拉取耦合）。

## 落选 / 不做

- issues 处置状态独立 JSON 文件：双写源，状态随 CR 行内走。
- 账本正文双向解析合并：违背 frontmatter 唯一权威态，成本高收益低；以醒目警告替代。
- writing-agent 整体引入:Python 依赖与零依赖纪律冲突；仅借其证据账本思路。
- 索引库/embed/RAG：维持 0004/0006 后置结论。
