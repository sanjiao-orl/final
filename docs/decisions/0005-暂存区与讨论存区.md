# 0005 · 暂存区与讨论存区的归属（core sqlite）

- 状态：已定稿（2026-08-08），第 3 周动工
- 铁律来源（01-产品定义）：**人的方向，AI 的笔**——AI 产出全部先进暂存区，批量采纳才落地。

## 决定

- **讨论存区 = core 会话加 `scope` 列**（`sessions.sqlite`，随作品 `.novel/` 走）：`''` = 无归属讨论，章 relPath = 章节内讨论。旧库自动补列迁移，老会话归无归属。
- **暂存候选 = core 新表 `candidates`**（同库，FK 到 sessions）：original（锚定原文）/ proposed（建议文本）/ instruction（指令留痕）/ status（pending → adopted | discarded）。不物理删，丢弃只是状态。
- **改写通道 = 独立端点 `POST /rewrite`**（SSE 纯文本流）：无工具、不落库、强约束系统提示（只输出改写后正文）。产出由壳另行 `POST /candidates` 进暂存区；整改 = 带上一版+整改要求重跑 /rewrite，patch proposed 与指令留痕。
- **采纳落地路径 = 编辑器内按 original 唯一定位替换 → write_chapter 保存**（历史快照安全阀自然生效）。定位失败（原文已变动/多处出现）显式报错，候选留 pending。
- 预览呈现：正文内联删除线（原文）+ 建议色插入（建议文本）+ ✓/× 单条操作；批量操作在暂存抽屉。

## 落选

- 候选放 domain（MCP 文件工具）：候选是会话伴生产品状态，不是手稿文件，domain 保持无状态文件工具；
- 候选只放壳内存：重启即丢，违背安全阀 ethos（AI 产出也是产出，不能无声消失）；
- AI 直接 write_chapter 改正文：绕过暂存区，违反铁律。
