## 规范

- 版本号：六处事实源（清单见 `scripts/check-versions.mjs`），core/domain 代码读 package.json；`npm run check` 内含校验，release.mjs 写完自检，漂移即失败。
- 提交：conventional commits 中文摘要；一切 git 写操作（commit/push/release）须作者明确指令。
- 文档分层与加载：活跃件=本件 + bugs.md；现行规范=`docs/reference/`（现状文体六件：01 产品定义/02 字数口径/03 协议契约/04 prompt与skill机制/05 账本与长篇连续性/06 完本书分层导入，front matter 带验证日期与 commit）；调研/排查/评审工作件=`docs/work/`（带 status front matter，只读当前任务点名单件）；未定稿草案=`docs/drafts/`（仅作者点名加载）；历史=archive（默认禁止加载，考古按需单点读，逐件索引见其 README，一律不改写）。
- 文档生命周期流水线：调研 → work →（批次收口封存）→ archive；决策 → drafts →（作者审定）→ 改写为 reference 现状文体（不带决策出处）→ 草案原件归档。**不再产决策文体文件**。批次收口 checklist：测试绿 → 本件更新 → bugs 核销 → work 件封存 → 有版则随版归档（本件批史段/已全结登记条/旧版本枚举移 archive 批史件，bugs.md 同口径——防膨胀的机制是归档，不是加新容器）。
- 文档防腐机械化：`npm run check:docs`（已并入 `npm run check` 与 CI 门禁）——current 禁手写版本头 / reference front matter 必带 last-verified+verified_commit / AGENTS.md ≤50 行（gitnexus 生成块豁免计行，作者裁决） / 活跃层禁引 archive 路径（`archive/件名` 短引用的考古指引允许） / work 的 sealed 件必移 archive / 协议三处版本相等且路由全量见于 03（以上 error）；体量超预算与决策文体特征词（warn）。
- 登记分工：作者口头强调的需求当场登记进「弱点与需求登记」节；具体可定位缺陷入 bugs.md；AI 发现规则可疑可登记异议；同一规则被反复纠正理解 → 登记入弱点节。「弱点与需求登记」「缓做」必须留在本件内防基线重置。
- prompt/skill：机制与写作铁律见 `docs/reference/04-prompt与skill机制.md`；预置 skill 无数量硬顶，书级试跑 + 真实写作验证留住才转正，候选试跑架 `core/prompts/candidates/`（flat 扫描不触及）；结构级检查（伏笔/时间线/口吻/知情权）永远是 domain 确定性工具的职责，不写成 skill。
- 安全口径：账本/问题日志路径白名单（`.novel/` 根下或 `editorial_notes/` 下 .md）；apiKey 打码回传 + 占位即保留；连接 token 不进日志；webview CSP 兜底 + LLM/markdown 输出渲染前过 DOMPurify 白名单净化（`shell/src/lib/sanitize.ts` 统一入口）；workDir 清洗后才许拼系统提示。
- 验证：改完必须 check/test/实跑，无法验证就明说；主 agent 审核不盲信回馈结论；发版前过亲测清单。
- 结构纪律：人审内容留 md、机械态/导生态可入 sqlite 或缓存（按「谁会编辑它」分流）；导生物可焚可重建；预处理走「脚本 → 导生物 → 主程序只读」，不拆仓；38 个 MCP 工具契约不动只做加法；新增理解层维度必须带证据锚 + 至少一条确定性诊断 + 注入预算上限。
