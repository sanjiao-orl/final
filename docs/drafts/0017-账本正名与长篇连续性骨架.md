## 决策

### 1. 兼容性不变量(唯一固定层)

三个不变量:**契约与事实源**(md 格式、38 工具契约只加法、证据锚、防泄露语义不动)、**数据与写作连续**(真账本不强制迁移、写作不停车)、**增量定义**(新结构进来,旧结构不拆、不改语义、不强制迁移)。
破增量红线四条(任何一条进施工案即可打回):强制旧维迁上区间基座;自由字符串改必填外键;动十条旧诊断语义;确定性检查变方案可配置。
既有红线全程生效:0011(不做知识图谱/游戏式状态机;确定性诊断+证据锚+LLM 提案作者裁决;人审内容留 md)、0004(索引接口预留、导生可焚)、0012(正文经暂存提案、账本经 upsert)、酒馆三不抄。**本层之外无默认**——初稿的结构答案不在本层,全部经 §2-§6 重推导。

### 2. 账本正名与统一事实信封

「四维账本」正名为「账本」;**维度改称事实类型(fact type)——有任务名的可增集合**(时钟/道具托管/承诺·伏笔/知情/角色,现五)。数据键与 ledger_* 工具名与类型数无关,零改动;旧文档不改写。

**统一事实信封(重推导结论,取代初稿「永久混合」)**:所有事实类型共享一个信封 `{type, payload, 区间, 锚, 面}`——payload=按类型各自 schema(现有五套 schema 映射为 payload schema,不丢字段);区间=生效区间原语 `{值, 起始章, 结束章|开放}`(外-b1 语义,过期≠矛盾);锚=evidence:{chapter,line,quote};面=冻结面/可补记面权限位(Letta 同构,外-b4)。收益是结构性的:提案机器只剩一条通用 apply 路径(否则五套形状各自适配、round-trip 测试乘五)、导生索引层几乎免费(一切自带区间)、注入预算一个机制管全部。

**生效区间全维原生(模型层)**:旧时间感字段(知情「截至章」、伏笔「预计回收卷」)映射进区间 payload——映射表以 4.3 时点小段真账本校准(仪器①挂期末考,0828 改法),校准前按保守映射(只增区间、不删旧字段语义)。**坐标优先级规约(0905 姊妹线回灌,novel-probe 叶/链坐标打架案)**:账本事实锚为坐标权威——摘要/索引/导生层坐标与账本锚冲突时,以账本锚为准、冲突本身入诊断清单;同一事实禁止双坐标无优先级。

**兼容迁移(文件层)**:md 永留、人审永留;旧格式双读永容忍——读路径归一化进信封,对旧账本零 diff;写入触及处按信封范式落笔(以 YAML 向后兼容快照测试全绿为闸门);归一化批处理脚本=事实源迁移(非预处理导生),作者显式触发、git 可 diff 可回滚、永不强制。模型层即日统一,文件层渐进收口——「强制迁移」与「永久混合」两端同否(被否选项 7)。

### 3. 图分层声明(一次性收口,维持初稿)

**事实源=类型化账本(md);图=导生(索引层+视图层),永不为源。** 导生索引层挂基准触发(§8 仪器②,4.5 视数字进 4.6);图数据库不做。视图层候选:知情星座图(角色×秘密二部图,读者/真相双视角)、全书状态面板(触发条件在块 4 落地后预期自动满足)。创作期关系构思画板归讨论存区家族:人审、随手画、不进事实源、不背对账义务。Graphiti/GraphRAG 仅作导生层实现参照(时态边+混合检索/层次社区摘要),挂同一触发。

### 4. 角色维=枢纽实体(信封原生的首个新类型)

- **静态层(登记型,低频人审)**:name(建议全名)/aliases/角色定位/阵营/自由描述(外貌、背景、性格——「一张 description+少量结构字段」行业共识,外-a1/a2)/关系骨架(自由文本或轻量列表,**不做结构化关系边**——行业弱项+红线)。0011 第 8 条设定登记(境界名/功法名/势力/地名术语)复用同模式同批承接。
- **动态层(提案型,高频)**:位置/生死/境界修为等=区间原生事实;**多级真相口子=知情分层标注**(读者视角/真相视角可各一条区间——外-b1 红线改造)。动态层永远走 §5 裁决回路,**不做「当前值」字段、不走直写**。字段集以 4.3 时点小段真账本校准(仪器①挂期末考,0828 改法;网文特有维度:境界/称谓,以真实正文试)。
- **信封原生首型**:角色条目按 §2 信封定义,作统一模型的第一个验证者——信封设计有角色维度背书才转正。
- **别名归一**:别名表+词典精确匹配+同形词排除表(外-a3)+中文称谓规则(原生空白,自建);确定性诊断两条起:人名写错=新人物检测、同一人多写法检测;0013 决策 6 点名的进阶单调性诊断同步设计。
- **三件套兑现**:锚=动态层每条自带;诊断=归一化+单调性;预算=角色切片注入上限(与 ledger_chapter_slice 同口径,数值 4.3 定)。
- **现有类型人名字段升级为可解析引用**:promise.holder/knowledge.character/prop 托管人可解析到角色条目;可选解析、不强制迁移、未解析不报错只入诊断清单。

### 5. 裁决回路:提案协议与统一裁决状态机

- 直写路径(chat 引导 ledger_upsert)保留不动。
- **提案=带条目 id 的操作序列**(ADD/UPDATE/DELETE/NOOP+证据锚+摘由,外-b4 Mem0 原语),应用走现有 upsert 管线(CAS/快照复用);**解析=generateObject+校验失败自动重试**(AI SDK 原生路径,零新依赖;Outlines 引导式解码属本地推理栈,BYOK 云端端点不可用——不采)。
- **统一裁决收件箱(重推导结论,取代初稿「提案流/预警雷达两套状态机两个面板」)**:预警=反向提案——系统提议作者关注某物,与写入提案同构(带 id、带锚、待裁决)。两者共用一台状态机:pending→adopted/discarded;**dismiss 必带理由枚举,「有意延后」一等公民**(选后改锚新预计卷);重报锚**卷锚**(进入新卷仍逾期/预计卷再顺延超阈值才重报);`expect` 反向绊线(「我预期第 X 卷出现 Y,没出现提醒我」,外-c3 rustc 语义)。处置率仪表统一(Google 定义:作者没采取任何行动=误报,外-c7)。
- **三档处置语义落位**(不改 0009 四级 severity 表达粒度):**拦**=同步写闸(protect 被提案触碰→deny,不进收件箱);**顶**=伏笔逾期→收件箱置顶;**列**=悬空、doNotReexplain→收件箱常驻清单。三张死表全部接确定性消费:protect=写闸+提案闸、tripwires=绊线正反两向、doNotReexplain=列档。
- **扫描器分工**:确定性预筛(正文提及命中已知名/别名→新人名/新称呼清单)先行,LLM 原子声明抽取+与账本/摘要双向匹配(外-b3)做发现;噪音预期按 F1≈0.68 设计。**超域处置规约(0905 姊妹线回灌,novel-probe 太阳圣徽案:超域代号 9 章 13 次提及被静默蒸发)**:高频出现但未命中任何已知名/别名的候选,不得静默丢弃——入候选队列标「超域疑似」,由裁决回路定去留。触发=重要性累计阈值/连载间隙批量,**不在写作热路径**。
- **基线先行**:雷达/扫描上线先拍卷/章快照,只报新增,存量入清单;写作态常驻零弹窗(todo-tree 模式),发布检查态才全量。
- **nursery 灰度**:新预警/新提案类型先入 nursery(仅清单可见),处置率高才升主动提醒。
- 消费者:补账扫描(4.2 起)与角色动态状态更新(4.3)共用同一机器;协议本稿锁定。
