# 账本与长篇连续性（块 4 结构规范）

「四维账本」正名为「账本」。维度改称**事实类型（fact type）**——有任务名的可增集合（时钟/道具托管/承诺·伏笔/知情/角色，现五）；数据键与 ledger_* 工具名与类型数无关，零改动，旧文档不改写。

## 兼容性不变量（唯一固定层）

1. **契约与事实源**：md 格式、38 工具契约只加法、证据锚、防泄露语义不动。
2. **数据与写作连续**：真账本不强制迁移、写作不停车。
3. **增量定义**：新结构进来，旧结构不拆、不改语义、不强制迁移。

破增量红线四条（任何一条进施工案即打回）：强制旧维迁上区间基座；自由字符串改必填外键；动十条旧诊断语义；确定性检查变方案可配置。

## 统一事实信封

所有事实类型共享一个信封 `{type, payload, 区间, 锚, 面}`：

- **payload**=按类型各自 schema（现有五套 schema 映射为 payload schema，不丢字段）；
- **区间**=生效区间原语 `{值, 起始章, 结束章|开放}`——过期≠矛盾；旧时间感字段（知情「截至章」、伏笔「预计回收卷」）映射进区间 payload，校准前按保守映射（只增区间、不删旧字段语义）；映射表以 4.3 时点小段真账本校准；
- **锚**=evidence `{chapter, line, quote}`，**账本锚为坐标权威**——摘要/索引/导生层坐标与账本锚冲突时以账本锚为准，冲突本身入诊断清单；同一事实禁止双坐标无优先级；
- **面**=冻结面/可补记面权限位。

兼容迁移：md 永留、人审永留；旧格式双读永容忍——读路径归一化进信封，对旧账本零 diff；写入触及处按信封范式落笔（YAML 向后兼容快照测试全绿为闸门）；归一化批处理脚本=事实源迁移，作者显式触发、git 可 diff 可回滚、永不强制。模型层即日统一，文件层渐进收口。

实测依据（净本 v1.2，300 章）：账本 2.45MB、ledger_slice 平均 44.0 万 / chapter_slice 49.2 万字符（双双超任何模型上下文——knowledge 无限累加+promises 全量注册表主导体积）；查询耗时无瓶颈（reconcile 2089ms/300 章）。含义：注入预算上限与区间裁剪是**实测生存条件**，不是优化项。

## 图分层

**事实源=类型化账本（md）；图=导生（索引层+视图层），永不为源。** 导生索引层为 4.1 起必备件。视图层候选（挂触发）：知情星座图、全书状态面板；创作期关系构思画板归讨论存区家族（人审、不进事实源）。图数据库不做。

## 角色维（信封原生的首个新类型）

- **静态层（登记型，低频人审）**：name/aliases/角色定位/阵营/自由描述/关系骨架（自由文本，不做结构化关系边）；设定登记（境界名/功法名/势力/地名术语）复用同模式。
- **动态层（提案型，高频）**：位置/生死/境界修为等=区间原生事实；多级真相口子=知情分层标注（读者/真相视角可各一条区间）；永远走裁决回路，不做「当前值」字段、不走直写。字段集以 4.3 时点小段真账本校准。
- **别名归一**：别名表+词典精确匹配+同形词排除表+中文称谓规则；确定性诊断两条起（人名写错=新人物检测、同一人多写法检测）；进阶单调性诊断同步。
- **超域处置规约**：高频出现但未命中任何已知名/别名的候选，不得静默丢弃——入候选队列标「超域疑似」，由裁决回路定去留。
- 现有类型人名字段升级为可解析引用（promise.holder/knowledge.character/prop 托管人）：可选解析、不强制、未解析不报错只入诊断清单。
- 三件套：锚=动态层每条自带；诊断=归一化+单调性；预算=角色切片注入上限（与 ledger_chapter_slice 同口径）。

## 裁决回路：提案协议与统一裁决收件箱

- 直写路径（chat 引导 ledger_upsert）保留不动。
- 提案=带条目 id 的操作序列（ADD/UPDATE/DELETE/NOOP+证据锚+摘由），应用走现有 upsert 管线（CAS/快照复用）；解析=generateObject+校验失败自动重试。
- **统一裁决收件箱**：预警=反向提案（系统提议作者关注某物），与写入提案共用一台状态机 pending→adopted/discarded；dismiss 必带理由枚举，「有意延后」一等公民；重报锚=卷锚；`expect` 反向绊线；处置率仪表（作者没采取任何行动=误报）。
- **三档处置语义**（不改 review findings 的四级 severity 表达粒度）：拦=同步写闸（protect 被提案触碰→deny）；顶=伏笔逾期→收件箱置顶；列=悬空、doNotReexplain→常驻清单。三张死表全部接确定性消费。
- **扫描器分工**：确定性预筛（正文提及命中已知名/别名→新人名/新称呼清单，超域走超域处置规约）先行，LLM 原子声明抽取+账本/摘要双向匹配做发现；噪音预期按 F1≈0.68 设计。触发=重要性累计阈值/连载间隙批量，不在写作热路径。
- 基线先行（只报新增，存量入清单）；写作态常驻零弹窗（todo-tree 模式）；nursery 灰度（新类型先入清单，处置率高才升主动提醒）。

## 批次结构（风险燃尽序）

- **4.0+ 对照实验前置批**：0018 对照实验（净本 v1.2 同台，~600 calls，纯脚本批）先于 4.1——产出裁决 0018 死活、供 4.2 选域、定慢环参数。
- **4.1 地基批**（行为零变独立发版）：核心四件=提案机器核心（信封 schema/操作序列/应用管线/权限面校验）+ 信封模型层双读（快照测试全绿为闸门）+ 最小索引层 + 冷读 ledger_slice 预算闸。最小索引层边界=按生效区间裁剪的信封切片器 + 名字/别名→区间条目的章级倒排；embedding 不碰。FTS5 路线注意：SQLite offsets() 已自当前版本内建移除（3.50.4/3.53.1 全分词器实测），坐标定位走章级 MATCH+highlight() 反推。ledger.ts 切刀、chat.ts 拆分、对账器缓存=并行独立线，不阻塞 4.1 出口。
- **4.2 薄切片裁决回路批**（全块扩容闸门）：选一个窄域跑通「预筛→扫描→提案→收件箱裁决→落账→回读验证」全环（首选承诺·伏笔维，选域由仪器④⑤裁决）；摘要-账本关联字段与冷读双契约拆分随批。出口=真实写作裁决负担数据，负担实证不成立→4.3/4.4 降规格或停。
- **4.3 角色卡批**：静态层登记型（直写+归一化诊断+注入预算+壳角色面板+可解析引用）；动态层接裁决回路。
- **4.4 预警雷达批**：三张死表接确定性消费、基线先行、nursery 灰度。
- **4.5 收口**：基准复测、北极星+三仪表报数（anchors 计数、补账漏登记数、预警处置率）。

## 前端触点（零新栏，五栏不动）

裁决收件箱（批量勾选+todo-tree 常驻+发布检查拦截点，提案与预警同面板）；ContextColumn 角色面板（静态卡+变迁时间线）；chat 注入可见性（角色切片/预警进「本次注入了什么」清单）。LedgerView 信封渲染升级归 4.3。

## 断言先行

信封 round-trip + YAML 向后兼容快照（旧账本双读零 diff）；区间代数确定性测试；归一化诊断确定性测试；提案机器序列化/幂等/权限面校验；状态机 dismiss→卷锚重报、写闸路径；promptfoo 薄切片用例随 4.2 落地。

## 重开权

骨架站在此结构之上，直到仪器与真账本证据说不然；4.2 裁决负担实证不成立可直接触发重估（回路死则全块扩容前提不成立）；信封查询代价实证劣于异构可复议存储面。仪器①（真实账本体检）挂期末考/4.3 真人小段时点触发，不向当前批索要。
