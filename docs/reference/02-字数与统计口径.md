# 字数与统计口径

> 登记起因：评审 R3 缓做 D9「字数双口径（countWords vs countCjk）文档说清」——两个计数函数语义不同、
> 各服务不同界面，此前口径只散在代码注释与测试断言里，没有一处对作者的说明。本件钉死两个口径的
> 定义、可见面与事实源坐标；改口径先改本件。

## 正文口径 countWords：非空白字符数

- **定义**：正文中每个非空白字符计 1——汉字、中英标点、字母、数字都算；空白（空格/换行/制表符）不算；
  **不计 frontmatter**；含 Markdown 标记字符（如 `#`）。
- **中文写作惯例**：网文平台按字符计费计字，标点算字，故正文统计用此口径。
- **可见面**：TreeView 章字数/目标进度与卷汇总、编辑器章头「N / goal 字」、码字日历（今日 +N 字）、
  章摘要机检字段 wordCount（首写冻结）。
- **事实源**：`domain/src/tools.ts` `countWords()`（list_structure / word_count 工具共用）。

## 汉字口径 countCjk：仅 CJK 统一表意字符

- **定义**：只计汉字（U+3400-4DBF Ext-A、U+4E00-9FFF 基本区）；标点/字母/数字/空白一律不算；
  不计 frontmatter。
- **用途**：质量与声口类指标要排除标点与拉丁字符的干扰，用纯汉字数当分母/基准——
  审阅报告「CJK 字数」指标（阈值 1800 目标/1500 底线/1000 红线段）、段落模板段资格、声口指纹的
  句长/对白占比分母。
- **事实源**：`domain/src/qualityScan.ts` `countCjk()`；同域正则 `domain/src/voice.ts` `CJK_RE`。

## 差异示例

`'正文十一个字符。abc 123'`（7 个汉字 + 1 句号 + 3 字母 + 3 数字）：

- countWords = **14**（全部非空白字符）
- countCjk = **7**（仅汉字）

## 为什么不统一成一个

两个口径回答不同的问题：「这一章有多长」（给作者与平台看，标点算字）与「正文密度/声口底数够不够」
（给机检看，标点是噪音）。合并任何一个都会让另一侧失真；差异在界面上各有名目（「字」vs「CJK 字数」），
不做换算。
